Parts 00.03 and 01.01 add no tables or columns; 01.02 adds three tables; 01.03 adds thirteen tables (configuration, numbering, change requests and a sample document); 01.04 adds five (event catalogue, inbox, jobs, schedules, a demonstration projection) and rebuilds the two change-request tables once, to take the request-type CHECK out; 01.05 adds three (files, upload sessions, file settings); 01.06 adds six (formulas, traces, shadow results, units, conversions, sample bills); 01.07 adds five (objectives, alert rules, alerts, metric samples, browser reports); 01.08 adds four (connectors, credentials, integration log, webhook receipts); 02.01 adds ten (users, credentials, MFA factors, devices, policy, sessions, refresh tokens, login events, login throttle, password resets); 02.02 adds nine (the organisation master); 02.04 adds six (permission registry, roles, role grants, field masks, assignments, legacy mapping) and alters nothing; 02.03 adds three (user profiles, invitations, role grants) and one index on `iam_users`, and alters no existing table: the new user fields live in a one-to-one table because SQLite has no ADD COLUMN IF NOT EXISTS, so an `ADD COLUMN` migration cannot be idempotent (ADR-74). Every migration is now verified in CI: it must apply, reverse to the exact previous schema and data, and re-apply (`npm run erp:migration-check`).
