## 2. What was built
- **Database** (migrations 179, 180; nothing existing altered): `bud_dept_budgets`, `bud_dept_lines`, `bud_dept_actuals`, `bud_alloc_rules`, `bud_alloc_runs`, `bud_alloc_lines`; seed: the flag, three navigation entries, four page-tracker rows, templates `bud.dept.approved`, `bud.dept.rejected`, `bud.alloc.posted` (English, Hindi).
- **Server** (`modules/bud/dept.js`, `alloc.js`): department budgets (create, update, delete draft, submit, withdraw, cancel, amend/new version, compare, history, print, export, import, spread helper), workflow `BUD_DEPT_BUDGET` with resolver `bud_dept_head`, actuals (event consumer `fin.gl.posted|reversed` and system endpoint), budget-vs-actual report with drill-down and CSV, allocation rules (draft, edit, activate by a second person, cancel, history, CSV), runs (preview, post, reverse, list, pool of a project for 23.10); events `bud.dept_budget.approved`, `bud.dept_budget.revision_started`, `bud.alloc.rule_changed`, `bud.overhead.allocated`, `bud.overhead.allocation_reversed`; object type and file entity `bud_dept_budget` (discussion, timeline, trace, related, attachments).
- **API**: 34 routes under `/api/v1/bud` (`dept-options`, `dept-budgets`, `dept-report`, `dept-actuals`, `alloc-rules`, `alloc`), in the route policy and `openapi.yaml`.
- **Permissions**: `bud.dept_budget.{view,create,edit,delete,submit,approve,cancel,amend,print,export}`, `bud.dept_report.{view,export}`, `bud.dept_actual.post`, `bud.alloc.{view,configure,approve,run}`. Head-office manager roles prepare (a department-scoped assignment limits them to one department); CFO and director approve; the accounts manager drafts rules and runs allocations; the CFO and director put rules in force; the auditor reads; only the system administrator posts ledger actuals.
- **Browser**: Department Budget Workbench (list; object page with Details, Lines, Attachments, Approvals, Timeline, Discussion, Related and Compare; grid of accounts by month with a server-side spread), Department Budget vs Actual, Overhead Allocation Rules (rules, run preview, posted runs); English and Hindi.
- **Docs**: ARCHITECTURE section 96, DB_CHANGES, DB_BASELINE, ADR-461 to 465, D-466, D-467, openapi.

## 6. Known limitations
D-466 (ledger, project accounting and revenue of the months not built: event contract, system endpoint, revenue basis = contract value), D-467 (import is JSON rows, no field masks needed, no timing at 100 000 rows). There is no department-head role code in the catalogue, so preparing is granted to the head-office manager roles and limited by department assignment (ADR-462). Allocation rules do not use the workflow engine: drafted by one person, put in force by another (ADR-465); runs are not approval-controlled.
