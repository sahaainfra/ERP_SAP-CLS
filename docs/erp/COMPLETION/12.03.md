## 2. What was built
- **Database** (migrations 177, 178; nothing existing altered): `bud_check_config`, `bud_commitments`, `bud_commitment_log`, `bud_actuals`; seed: the flag, two navigation entries, two page-tracker rows, templates `bud.check.config_approved` and `bud.check.over_budget`.
- **Server** (`modules/bud/ledger.js`): the check and availability, commitments (create, amend by difference, short-close, cancel, replace), actuals (post, reverse, consume once), the report with drill-down and CSV, reconciliation, settings (propose, cancel, history, import, export) with workflow `BUD_CHECK_CONFIG`, control point `CP-BUD-01`, consumers of the commitment and actual event families; events `bud.commitment.changed`, `bud.actual.posted`, `bud.check.config_changed`.
- **API**: 14 routes under `/api/v1/bud` (check, availability, ledger, commitments, ingest, check-config), in the route policy and `openapi.yaml`.
- **Permissions**: `bud.ledger.{view,export,post}`, `bud.check.{use,view,configure,approve}`; project manager and project controls manager propose settings and read the ledger; project director and director approve settings; every spending role may use the check; only the system administrator posts to the ledger.
- **Browser**: Budget vs Committed vs Actual (report with drill-down and the availability probe), Budget Check Settings (config), component `AvailabilityPanel`; English and Hindi.
- **Docs**: ARCHITECTURE section 95, DB_CHANGES, DB_BASELINE, ADR-454 to 460, D-463 to 465, openapi.

## 7. Full regression result
`npm run erp:regression` (run three times: the first two were invalidated, see below): **14 of 16 steps passed** (ESLint, TypeScript, coverage gate, migration up/down, schema lint, tokens, icons, navigation registry, route registry, data-integrity, schema-diff, golden outputs, secret scan, build, installable app). **Unit, API and permission tests failed on one test only, `punches.test.js` "a morning burst" (D-455, random, not this part).** **Browser stage: 13 failed, 55 skipped, 484 passed (1.7 hours); no failure is in `budget.spec`, `budget-changes.spec` or `budget-check.spec`.** The failures are the load-sensitive families already recorded (`a0-visual`, `estimate`, `mto`, `operations-health`, `training`, `data-health`, and the desktop page sweep `pages.spec`, which reached its 30-minute limit under load). `pages.spec` was run alone afterwards and **passed** (28.2 minutes, every registered page including the budget pages); `responsive.spec` passed in the full run (9.9 minutes). The step is therefore not green (D-424, D-430, D-455).

What went wrong on the way, honestly: the first run failed ESLint (an unused helper I left in `e2e/budget-check.spec.js`; fixed); an interrupted run left test servers and browsers behind that made the unit stage hang for four hours; and the tracker row of the settings page used a page type the tracker does not have (`CONFIG`), which the database dropped silently and `migration-api.test.js` then reported (fixed to `FORM`). None of these remains.
