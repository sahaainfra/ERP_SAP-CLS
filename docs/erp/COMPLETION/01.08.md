## 1. Discovery summary
The repository had the event bus and jobs, the interim approval engine, the audit trail, redaction and correlation (01.07) and a public router for signed links (01.05), but no connector registry, credential store, outbound call wrapper or webhook receiver, and no module called an outside service. Decision per requirement: `docs/erp/DISCOVERY/01.08.md`. Departures from the pack: dedicated providers (SMS and WhatsApp gateways, GST, banks, biometrics, AI) belong to the parts that use them, so this part ships the framework, a sandbox and an HTTP email provider, and a generic HTTP JSON provider for the other types (D-052); switching a connector off is immediate rather than an approved request (ADR-59); connector codes are unique system-wide because the public webhook URL names the connector before any company is known (ADR-60).

## 2. What was built
- **Tables** (migrations `20261030000020` and `20261030000021`, up and down): `core_connectors`, `core_connector_secrets`, `core_integration_logs`, `core_webhook_receipts`; flag `ff.core.p0108` (default OFF, ON in development and test).
- **Vault**: AES-256-GCM with a random nonce per value, bound to the connector and key name; `VAULT_KEY` required in staging and production. A new value is staged with the change request and becomes active only when it is approved; the old one is retired. Only the integration service can decrypt, and each use writes an audit row naming the keys.
- **Provider abstraction**: registry with a typed interface per connector type (email needs `send`); built in `email/sandbox`, `email/http_api` and `http_json` for the other nine types. Plain http is accepted only for localhost outside production.
- **Call wrapper** `integrations.call(code, operation, payload, opts)`: connector and payload checks, per-connector rate limit, circuit breaker, timeout, retries with doubling back-off for timeouts, network errors, 5xx, 408 and 429, idempotency key and correlation ID passed on, one redacted log row per call, tracing span, health events when the circuit opens or closes.
- **Log**: request and response redacted, message bodies omitted, every secret value of the connector removed; user pseudonymised; retention per connector with a daily purge job; connection health job every 15 minutes.
- **Webhooks**: `POST /api/v1/core/webhooks/:connector`, HMAC-SHA256 over timestamp and body, five-minute tolerance, delivery ID for replay protection, verified payload published as `core.webhook.received`.
- **Approvals**: new connector, setting or limit change, credential rotation and switching on are `connector_change` requests: ITADM asks, SYSADM approves, and the CFO also for bank and GST connectors. Disabling is immediate and audited.
- **Pages** (behind `ff.core.p0108`): Connectors, Connector Configuration, Integration Log. **Roles**: ITADM `core.connectors.configure`; ITADM and SYSADM `core.connectors.view`; CFO decides bank and GST requests in Approvals.
- **Repair found on the way**: the feature-flag override dialog listed only the flags on the current page, so with more than 25 flags some could not be overridden; it now lists every flag.
- Docs: `ARCHITECTURE.md` section 17, `DECISIONS.md` ADR-55 to ADR-60, `DEFECTS.md` D-052 to D-058, `DB_CHANGES.md`, `DB_BASELINE.md`, `openapi.yaml`, `.env.example` (`VAULT_KEY`); `schema/baseline.json` re-locked.

## 7. How to verify manually
1. `npm run build`, `npm start`, role ITADM, Administration > Integrations > Connectors > New connector: type Email, provider Sandbox, code `mail.main`, from address, an API key, switch on, reason, Request connector. It shows "Waiting for approval".
2. Role SYSADM, Approvals: approve it. Back as ITADM, Test connection (Healthy), open the connector, Send sample message.
3. Integration Log: the send call with its correlation ID; Details shows the redacted request, with no message text or key.
4. Connector page: Ask for a change (raise calls per minute, enter a new API key); it waits under Approvals; the credentials table never shows a value.
5. Add a webhook signing secret through a change request and send a signed request: see `docs/erp/ARCHITECTURE.md` section 17 for the signature; a replay answers `duplicate: true`.
6. `NODE_ENV=test node --test tests/integrations.test.js tests/connectors-api.test.js`; `npm run erp:regression` runs everything.
