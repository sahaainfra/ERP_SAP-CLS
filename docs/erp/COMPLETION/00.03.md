## 2. What was built
- **Pipeline**: `npm run erp:regression` now runs lint, type check, tests with coverage, coverage gate, migration up/down check, schema-diff, golden outputs, secret scan, client build and Playwright E2E (desktop and mobile). `.github/workflows/ci.yml` runs it on every pull request and push to main, plus `security` (dependency audit, secret scan), `codeql`, `package` and a `staging-rehearsal` job. `CODEOWNERS` added.
- **Migration safety**: `scripts/lib/migration_check.mjs` (every migration needs a down script that restores the exact previous schema and rows and re-applies cleanly); restore point (`VACUUM INTO`) before every deploy.
- **Release**: `npm run release -- <patch|minor|major>` (version bump, `CHANGELOG.md`, user release notes with the feature-flag list, annotated tag with `--commit`); `npm run package` (artefact with `build-info.json` and `SHA256SUMS`).
- **Deploy and rollback**: `npm run deploy`, `npm run rollback`, `npm run rehearse` (`scripts/lib/deploy.mjs`). Deploy verifies checksums, backs up, migrates, starts, smoke-tests, and rolls back by itself on a failed migration or smoke test. Rollback prefers down-migrations (keeps data), falls back to the restore point.
- **About**: `GET /api/v1/core/about` and the page Administration > About (version, build ID, commit, built at, deployed at, environment, runtime, migrations applied). Permission `core.about.view` for SYSADM and ITADM. Page registered in the minimal shell navigation. Migration `20261030000004` seeds `ff.prog.p0003`.
- Runbook: `docs/erp/RELEASE.md`.

## 7. How to verify manually
1. `npm run erp:regression`; open `reports/regression/report.html` and see every stage PASS.
2. Break something on purpose and watch the gate fail: add a failing test, or add `migrations/20261101000001_x.up.sql` with no `.down.sql` and run `npm run erp:migration-check`; or put a made-up AWS-style access key (the letters AKIA followed by 16 capitals or digits) in a new file and run `npm run erp:secret-scan`. Undo each afterwards.
3. `npm run rehearse`; read the PASS lines and `reports/rehearsal.json`.
4. `npm run build`, `npm start`, open http://localhost:3000, click About as SYSADM (version, build `dev`, 4 migrations); switch the role bar to PM and see the no-access message.
5. `npm run package` then `npm run deploy -- --env staging --artifact artifacts/<buildId> --port 3300`; open About on port 3300 and see the real build ID; `npm run rollback -- --env staging` needs a second deploy first.
6. `npm run release -- minor --dry-run` and read the changelog, release notes and flag list.
