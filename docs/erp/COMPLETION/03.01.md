## 1. Discovery summary
The token stylesheet was a copy of the prompt pack's reference with no source or generator in the repository; three themes worked, saved per browser and (since 02.03) in the profile; density variables existed but were not used; IBM Plex was named but not installed; there was no icon set, style guide, contrast check or colour lint. Decision per requirement: `docs/erp/DISCOVERY/03.01.md`. Departures from the pack: tokens are code reviewed in pull requests rather than runtime configuration, so they have no approval screen (ADR-110); the Tailwind preset is generated but Tailwind is not adopted in the build (D-114); Hindi switches the typeface while the screens other than sign-in are not yet translated (D-116).

## 2. What was built
- **One source** (`src/shared/design/design-tokens.json`): the reference tokens (IBM Plex Sans, primary #1D4F91, accent #F2A900, dark shell #1C2530) plus a display size of 32, the comfortable and compact densities, a muted status, the backdrop and QR colours, and the status semantics. `scripts/build_tokens.mjs` writes `src/client/design-tokens.css` and `src/shared/design/tailwind.preset.js` and, with `--check`, fails the regression if either is out of step or any text pair falls below WCAG AA.
- **Themes**: light, dark and high-contrast on `<html data-theme>`; a first visit follows the device (dark, or more contrast); the choice is saved per person and applied after sign-in on any device; the shell's theme menu and the Appearance panel both save it.
- **Density**: comfortable (default, 44 px controls, 48 px rows) and compact (28 / 32 px, smaller table text) on `<html data-density>`; controls, buttons, table cells and table text follow it.
- **Typography**: IBM Plex Sans, Plex Sans Devanagari (used for `lang="hi"`) and Plex Mono, served by the application from the `@fontsource` packages; fonts are kept as files so the content security policy stays at `font-src 'self'`.
- **Icons**: `<Icon name>` reads the registry key (13 groups, 34 actions, 11 states, 175 modules) and draws the Lucide glyph from a map generated from the registry, or one of 14 original construction drawings on the same 24 px grid and 1.75 px stroke.
- **Status semantics**: `statusTone` and `StatusBadge`: Draft neutral, Submitted and In review info, Approved and Completed success, Returned and At risk warning, Rejected, Overdue and Critical error, Cancelled muted, with an icon and the word.
- **Contrast**: 135 text and background pairs in the three themes pass WCAG AA; the high-contrast theme passes AAA on every pair.
- **Lint**: `erp/no-hardcoded-color` refuses a hex, rgb() or hsl() colour in client code; a test refuses them in the stylesheet; the two values that were there became tokens.
- **Preferences** (`ui_user_preferences`, module `ui`): `GET/PATCH /api/v1/ui/preferences` for theme, density, language of the screens, start page and table settings; one's own row only; optimistic version (409 when another device changed it first); audited; event `ui.preferences.changed`.
- **Pages**: Design System (`/admin/design-system`: three theme previews side by side, the contrast report with filters, colours, chart palette, status, typography in English and Hindi, density previews, spacing, radius, elevation, motion, layers, breakpoints, every icon with search and group filter, export of the tokens) and Appearance in My Profile (theme, density, language of the screens, start page; live preview, Save, Cancel).
- **Roles**: every signed-in person: own preferences; SYSADM (and SUPADM): `ui.styleguide.view`; outside production the style guide is open to everyone signed in.
- Packages added (with your approval): `@fontsource/ibm-plex-sans`, `@fontsource/ibm-plex-sans-devanagari`, `@fontsource/ibm-plex-mono` 5.3.0 (OFL-1.1) and `lucide-react` 1.66.0 (ISC), pinned.
- Docs: `ARCHITECTURE.md` section 25, `DECISIONS.md` ADR-109 to ADR-114, `DEFECTS.md` D-114 to D-118, `DB_CHANGES.md`, `DB_BASELINE.md`, `openapi.yaml`; `schema/baseline.json` re-locked (298 objects; 295 unchanged, 3 new).
