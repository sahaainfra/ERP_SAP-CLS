# Part 30.02 — Data Traceability & Reconciliation Suite

Execution step 220 · 2026-11-23 · Branch `ccr-a3b3ce3d-65llwf` · **In progress**: built and tested behind `ff.qa.p3002`. Formal acceptance waits for 30.01 and the company's G1/G2 sign-offs.

## 1. Discovery

Several owners already reconcile their own figures:

- the posting engine reconciles the sub-ledgers against their control accounts;
- the bank reconciliation statement reconciles bank and book;
- stores check the ledger against the balances;
- billing reconciles quantities project by project.

The suite runs them together for the whole company, adds the cost and payroll chains, and measures trace completeness. See the [discovery note](../DISCOVERY/30.02.md).

## 2. What was built

The page is `/admin/reconciliation-health` (**Administration → Reconciliation Health**), an overview page:

- **Key figures**: trace completeness first (% linked of the derived records, against the 99.9 % target), then:
  - critical differences;
  - checks failing;
  - the money tolerance.
- **A card per check** (FR-02): its status, how many figures were compared, how many are above tolerance, the total difference, the owner part, the owner's page, and **View all ›** to its exceptions.

  | Check | Compares | Source |
  |---|---|---|
  | QTY_CHAIN | Cumulative billed quantity of each BOQ line ≤ approved measurement | Client bill items, MB entries (22.x) |
  | COST_CHAIN | No double counting: the same document as an actual from two sources; consumed on a commitment = actuals booked against it; nothing consumed beyond the commitment | Budget ledger (15.04) |
  | SUBLEDGER_GL | AP, AR, inventory, GRNI, retention, advances against their control accounts; failed postings | `postingOf(db).reconcile` (23.02) |
  | STOCK_BALANCES | Balance on hand = sum of the stock ledger, by store and item | Stores (16.02) |
  | PAYROLL_GL | Approved payroll posted within `tst.recon.payroll_post_days`; posted net pay = the run's | Posting log (24.05) |
  | BANK_BOOK | Bank balance = book adjusted for items in transit, per active account | `cashOf(db).brs` (23.06) |

- **The checks run as a read-only reconciliation account** (CFO and AUD rights), so a run started by the QA lead sees the same figures as the nightly run (ADR-756). Amounts are shown, exported and notified only to holders of `tst.recon.amounts` (CFO, AUD, DIR). The QA lead sees the differences and statuses with the amounts masked.
- **BR-01**: every difference above tolerance is Critical, and the run is RED until it is cleared. The tolerances are parameters changed only through the 29.01 maker-checker (ITADM then CFO or a director, ADR-757):
  - `tst.recon.tolerance_paise`;
  - `tst.recon.qty_tolerance_milli`;
  - `tst.recon.trace_target_bp`;
  - `tst.recon.payroll_post_days`.
- **Trace completeness** (FR-01) counts two kinds of link:
  - every record whose `source_type` (or `src_type`) names a table must point at a record that exists;
  - every hand-off of the 30.01 threads that requires a source must find it.

  The groups with missing sources are listed with sample ids. The trace panel of a document reaches the payment and the receipt (the document flow repaired in 30.01).
- **Charts**: differences by check (drill to the check), and the runs over time (critical differences, trace %).
- **My pending actions**: the checks to clear and the records to link.
- **Exceptions**: failing by default, filterable by check, status and text, with paging, a sticky total, and a link to the record behind each.
- **Runs** (FR-03): **Run the reconciliation now** queues the job `tst.recon.run`; the nightly schedule runs at 02:50 IST.
  - Results are stored per figure (`tst_recon_results`).
  - Events: `tst.recon.completed`, and `tst.recon.difference_found` per failing check.
  - Alert `tst.recon.alert` (in-app, and e-mail for the nightly run) to every holder of `tst.recon.view` (CFO, AUD, DIR, QA lead) and to the person who ran it.
- **Export**: XLSX, CSV or PDF with the person's masks, audited.

**Permissions**:

| Role | Grant |
|---|---|
| CFO | View, run, export, amounts |
| AUD | View, export, amounts |
| DIR | View, amounts |
| ITADM, SYSADM (QA lead) | View, run, export |

## 6. Known limitations

D-801 (→ 30.04):

- No EAC check and no ageing tie-out.
- The payroll check compares the net pay only.
- An account without a statement is skipped.
- There is one money and one quantity tolerance for all checks.

The trace completeness measures links that exist in data; a record that should name a source but names none is caught only where a 30.01 hand-off requires it.

## 7. How to verify manually

1. Set `ff.qa.p3002` for a test company.
2. As the CFO, open **Administration → Reconciliation Health** and click **Run the reconciliation now**. The key figures appear with trace completeness and a card per check.
3. Open **View all ›** on a failing check. Each row shows expected, actual and difference, with a link to the record.
4. As ITADM, open the same page: the same rows, with the amounts shown as Hidden.
5. In **Enterprise Control Center → Request a change**, ask to set `tst.recon.tolerance_paise`. ITADM, then the CFO, must approve; the next run uses the new tolerance.
