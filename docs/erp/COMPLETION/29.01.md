## 1. Discovery

The approval engine over `core_change_requests` is the existing maker-checker framework, and this part builds on it. See the [discovery note](../DISCOVERY/29.01.md).

## 2. What was built

New module `admin` (`src/server/modules/admin`). The page is `/admin/control` (**Administration → Enterprise Control Center**), with pill tabs:

- **Governance (FR-02)** has live tiles, each drilling to its list:
  - admin approvals waiting (and how many wait for you);
  - open segregation-of-duties violations;
  - active privileged access;
  - dormant accounts (no sign-in for 90 days);
  - failed jobs and failed integration calls (7 days);
  - failing integrity checks;
  - last backup (29.06);
  - licences and certificates expiring in 30 days;
  - AI calls and cost this month;
  - emergency actions past their ratification.

  A red banner shows when read-only mode is on.
- **Admin approvals**: the worklist of change and ratification requests, with each one's chain, step, history and approve / return / reject (a comment is needed to return or reject).
- **Request a change (FR-03, BR-01)**:
  - choose a feature flag or a parameter;
  - see its current value, give the new value and a reason, and send it.
  - **Chains**: SYSADM → ITADM. A financial key (fin, bill, pay, proc, ctr, bud, close, tax) goes ITADM → CFO or DIR; a security key goes ITADM → DIR.
  - **Applying**: the change is applied by its owner (flag service, parameter service) only on the last approval. If the value changed meanwhile, it is refused (409). The maker can never approve.
  - **Direct edits**: while the control center is on, the old direct edit of company flags and parameters is refused (422), so nothing bypasses the checker (AC-04).
- **Emergency controls (FR-05)**: these act at once, are logged, and each raises a ratification request for ITADM or DIR, due in 24 hours:
  - read-only mode: every write of the company gets 423 until it is ended, while reading, signing in and the controls themselves keep working;
  - switch a feature off;
  - sign everyone else out.
- **Export & import (FR-03)**:
  - take a snapshot of the company's flags and parameters, with a SHA-256 checksum;
  - export it (`erp-config/1`);
  - load another environment's export: a file whose checksum does not match is refused. The diff lists every key that is different, only here or only in the file, with both values;
  - the chosen differences are raised as change requests.
- **Company onboarding (FR-04)**: the steps (settings, financial year, numbering, chart of accounts, users with roles, projects), each checked against its owner's records and linked to the page that completes it.
- **All settings (FR-01)**: the settings pages you may open, searchable, and the recent configuration requests.

Labels are en/hi/te (area `adm`). Count tiles on 28.03–28.05 now show whole numbers (they showed "0.00").

**Permissions**:

| Role | Grant |
|---|---|
| SYSADM | Make changes, snapshots, onboarding, emergency controls |
| ITADM, DIR | Check (by chain role), emergency controls |
| CFO | Checks financial keys |
| AUD | Reads |

## 4. Tests

`tests/admin-control.test.js` has four tests, all passing:

1. **Maker-checker**: one open request per key; the maker cannot approve; IT approves; the two-step financial chain; a rejection needs a comment; out-of-range values are refused; a stale request gets 409; the direct edits are refused.
2. **Emergency controls**:
   - read-only gives 423 on writes, and even decisions wait until it is ended;
   - ratification by another checker;
   - the kill switch, which cannot switch off the control center itself;
   - force logout ends the sessions;
   - the overdue count on the dashboard.
3. **Snapshots**: export, no difference with itself, the exact diff, a tampered file refused (422), and import as change requests.
4. **Catalogue, dashboard, onboarding and volume**: the catalogue and its search, the onboarding steps, the roles, and 100,000 change requests listing in under 500 ms.

`e2e/admin-control.spec.js` passes on desktop and mobile:

1. The dashboard.
2. A flag change requested by SYSADM and approved by IT in the page; applied only then.
3. Read-only mode on, shown on the dashboard, a write refused (423), then ended.
4. A diff against an uploaded UAT file, with one difference raised.
5. Onboarding.

Regression: `i18n-api` (namespace `adm`), `architecture`, lint, typecheck (0 errors), route, nav, schema lint, migration up/down, schema-diff and the permission audit.

## 6. Known limitations

D-789:

- The control center's own requests cover flags and parameters; the other areas keep their parts' maker-checker flows.
- Onboarding is a checklist with links, not a single creating wizard.
- Expiries are those of controlled documents.
- A rejected ratification is not reverted automatically.

## 7. How to verify manually

1. In a test company, set `ff.admin.p2901`.
2. As SYSADM, open **Administration → Enterprise Control Center**. Under **Request a change**, pick `ff.ai.p2801`, the new value and a reason, and send it. The flag is unchanged.
3. As ITADM, approve it under **Admin approvals**; the flag changes.
4. Under **Emergency controls**, give a reason and **Make the company read-only**. Saving anywhere is refused; **End read-only mode**.
5. Under **Export & import**, take a snapshot, export it, edit a value, and load it back. The diff shows that key.
