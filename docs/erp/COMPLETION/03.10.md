# Part 03.10 completion: existing screen migration onto the design system

Status: **Ready for review, with the open items below, the main one being that no module owner has signed off yet (D-169).** Feature flag `ff.ui.p0310` (OFF by default, ON in development and test).

## What was found
The repository began empty (00.01), so there was no older product to migrate: every one of the **66 pages** was built on the design tokens and the shell as it was written. The inventory of 00.01 (26 pages) was stale. This part therefore did three things: made the real list of pages a tracked, tested set; proved every page against the part of the Page Completion Checklist a machine can check and fixed what failed; and built the means by which the owners verify pages and old addresses redirect. No route has ever been renamed (checked over the whole history), so there is no old address to redirect yet.

## What was built
- **Tracker** (`ui_page_migration`, migrations 54 and 55): one row per page of the client registry (66 + the tracker's own page = 67): module, label, address, old address, page type (Dashboard, List report, Object page, Form, Worklist or Report), owner role (core: ITADM, iam: SYSADM, ui: PCMGR), status, who migrated and who verified, the part a page is scheduled to, defects. A test keeps the tracker and the registered pages the same set. Seeded as Migrated (never Verified).
- **API** (`/ui/page-migration`, 9 routes, permissions `ui.migration.view` and `ui.migration.signoff`): list with filters and the progress by module and page type; export (XLSX, CSV; audited; honours the filters); add and resolve a defect; verify, reopen or schedule a page (verify: the holder of the owner role, not the person who migrated it, no open High or Critical defect; reopening makes the reopener the migrator); sign off a whole module; ask for the old address of a page (a change request that another system administrator approves, audited; the address must start with one slash, cannot be a real page or another redirect).
- **Redirects** (FR-04): the browser that lands on an address that is no page asks the tracker once and goes to the page with the query string and fragment kept (`platform/migration/redirect.js`).
- **Screen Migration Tracker page** (`/admin/migration`, technical console, Report): progress strip, stacked chart by module and status whose bars filter the table, parameter panel, table with a total, details of a page (defects, verification, scheduling, old address), module sign-off, old-address requests with approve and reject, export. "Schedule by e-mail" waits for the report service (D-170).
- **Page checks** (`e2e/pages.spec.js`): every page opened at 360, 768 and 1280 px as a super administrator: inside the shell, one level-1 heading, a title, loading ends, no placeholder text, no console error, no sideways scroll, axe serious/critical none.
- **Visual baseline** (`e2e/a0-visual.spec.js`, 594 images, 41 MB): the first screen of every page, light, dark and high-contrast, at 360, 768 and 1280 px (`npm run test:visual`; `test:visual:update` renews on purpose). The file runs first, on a database nothing else has used; pages that show the clock or the whole system are compared with their content hidden.

## Defects found and fixed by the checks (recorded on their pages, P-1 to P-3)
- The connector page had no level-1 heading when no connector was chosen.
- The Roles page scrolled sideways at tablet width: the hidden label of the last column escaped its scroll area (fixed for every table).
- The Navigation Registry kept a loading box of its closed history dialog.
- Found along the way: the data-integrity suite judged the search index's `status` column against the standard workflow states (the column holds each record's own status): renamed `record_status`; the tracker's own statuses are registered with the suite (these only showed once a seeded table existed, in the full end-to-end run).

## Click-path for a reviewer
1. As the IT administrator open **Technical Console > Screen Migration Tracker**: 67 pages, none verified; choose a bar of the chart (a module and a status): the table filters.
2. Open **Details** of *Feature Flags*; add a defect of severity High; try to verify it (refused: High or Critical open); resolve the defect; verify it (it is now Verified in your name). Sign in as a system administrator: *Sign off Core platform* is refused (not the owner).
3. As the IT administrator **Sign off Core platform**: every core page without a blocking defect is verified; the others are listed.
4. As a system administrator open the details of *Users* and request the old address `/admin/people`; as a second system administrator approve it on the tracker; open `/admin/people?q=x#top`: it lands on Users with the query kept. An address nobody registered goes Home.
5. Export XLSX with a filter: the file has only the filtered pages; the export is in the audit trail.
6. `npm run test:visual` compares all 594 images; `npx playwright test e2e/pages.spec.js` checks every page.
