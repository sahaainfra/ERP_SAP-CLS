## 1. Discovery summary
See `docs/erp/DISCOVERY/06.03.md`. No item master existed. The existing materials were:
- free-text item codes in the calculation engine's conversions (01.06, D-042);
- free-text descriptions on the sample request lines (03.02).

Reused:
- units, HSN/SAC and GST rates on a date (06.02);
- name similarity (06.01);
- the workflow engine with conditional steps and the approval matrix;
- the List Report with saved views and exports (03.03);
- record registry, files, collaboration tabs, the Excel engine and notifications.

## 2. What was built
- **Database** (migrations 100 and 101, nothing existing altered): nine tables with the standard columns. The seed adds a system category tree of 13 categories, each with an attribute template, code prefix, item types, default HSN/SAC, GL code and steward role.
- **Service** (`modules/mdm/items.js`, ADR-254 to 258):
  - **Categories:** each company gets its own copy of the system tree on first use.
  - **Requests:**
    - a request is checked against the category: its types, its attribute template (required fields, choices, numbers), the base unit (06.02), the category's HSN/SAC and the GST rate on the date, tracking flags and rates;
    - its code comes from the category series (`CEM-00001`, BR-03);
    - a migrated material may keep its old code (`mdm.item.migrate` only).
  - **Approval:** by the steward of the category, through workflow `MDM_ITEM` with one conditional step per steward role (PROCMGR, STOREMGR, EST, PLANTMGR). The requester never approves. Return, resubmit and reject work, and the requester is notified.
  - **Duplicate check** (FR-07, T-02): a normalised specification key (case, spaces, units; brand ignored) and a name 90% alike, reported before sending. Sending anyway needs explicit confirmation.
  - **Item units** (T-01): written into the calculation engine as `CODE@company`, so the engine converts per item: 20 bags = 1 MT = 1,000 kg for cement.
  - **Bills of resources** (FR-04, BR-02): quantity, unit and wastage per component, with a cycle check and a cost roll-up for people who may see rates.
  - **Versions** (FR-05, BR-01): an item used in a transaction keeps its base unit. A new version from a date is approved like a new item and supersedes the old version on approval. Makes are approved by a second steward; alternates are supported.
  - **Where used:** bills of resources, alternates, the migration map and transactions. The sample request lines are the first transaction source; later modules register theirs.
  - **Selector** (FR-06, T-03): search by code prefix, words of the name, specification or category, with favourites and recent items. Rates are hidden without `mdm.item.rate.view`.
  - **Migration of old materials** (FR-08): candidates are listed; each is mapped to an item or becomes a new one. Old records are not rewritten.
- **Integration:**
  - the Item Master register on the List Report (`mdm.items`) with saved views, column chooser and XLSX/CSV/PDF export, rate hidden where not permitted;
  - a platform hook (`listExports`) so a module's list can use the List Report's export service (ADR-259);
  - form lookup `/mdm/lookups/items`;
  - Excel import `MDM_ITEM` (each row is a request) and export `mdm.items`;
  - object type and file entity `mdm_item` (documents, timeline, discussion, search);
  - events `mdm.item.requested`, `mdm.item.approved`, `mdm.item.changed` and `mdm.item_category.changed`;
  - an approval-matrix default for `MDM_ITEM`.
- **Browser:**
  - Item Master (category tree beside the List Report);
  - Item (object page with Details, Units with a conversion check, Specification, Bill of resources with the selector, Makes and alternates, Documents, Usage, Price history, Approvals, Timeline, Discussion);
  - New Item wizard (category and type → template attributes → name, units and tax → review with the duplicate check; the draft is kept in the browser);
  - Item Categories & Attribute Templates;
  - Item Migration;
  - the reusable Item Selector (`platform/items/ItemSelector.jsx`), used in the sample request lines (AC-01), the bill of resources, alternates and migration.
- **Permissions:**

  | Permission | Roles |
  |---|---|
  | read and request (`mdm.record.view`) | every internal role |
  | `mdm.item.edit`, `mdm.item.import` | PROCMGR, STOREMGR, EST, PLANTMGR (a change also needs the category's steward role) |
  | `mdm.item.rate.view` | the stewards and QS, ACCMGR, CFO, PM, PD, DIR, AUD, COMMGR |
  | `mdm.item.category.edit` | PROCMGR, EST, SYSADM |
  | `mdm.item.migrate` | PROCMGR, SYSADM |

- **Documents:** ARCHITECTURE section 57, DB_CHANGES, DB_BASELINE, DECISIONS ADR-254 to 259, DEFECTS D-299 to D-302, openapi, PROGRESS.csv (row 51), screenshots in `docs/erp/screenshots/items/`.

## 7. How to verify manually
1. **Request an item:** as a site engineer open **New Item**. Choose Civil materials › Cement and Material, fill the template (grade, IS standard, packing), name it and choose base unit MT. Add the unit BAG = 0.05 MT, review and send. If cement OPC 53 already exists, the review shows it and asks you to confirm.
2. **Approve it:** a procurement manager approves it in **My Approvals**. The item is active with code CEM-0000n.
3. **Convert units:** open the item, tab **Units**: 40 BAG to MT gives 2.000.
4. **Keep a bill of resources:** as an estimator create a work item (category Work items) and have another estimator approve it. On tab **Bill of resources** choose **Add components**, pick cement and sand, give the quantities and save; the cost per unit shows.
5. **Use the selector in a line grid:** as a project manager open **Sample Material Requests**, choose New, then **Add items from the catalogue**. Search "opc", choose it and add: a line with its code, name, unit and rate appears.
6. **Browse the catalogue:** open **Item Master**: the category tree beside the list, with views, columns and export.
7. **Migrate an old material:** open **Item Migration**. Map an old material to an item, or create the item from it.
