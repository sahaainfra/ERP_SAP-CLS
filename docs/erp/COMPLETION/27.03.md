## 2. Delivered

**Metric Catalogue** at `/bi/metrics` shows the Project Count definition, source lineage, certification, live scoped count and monthly capture quality. Project Count counts the visible entries of the source register. Its definition uses the Project Status dataset version and the owning project service. The standalone metric API also returns the lifecycle breakdown.

Company-level PCMGR and CFO users can request certification or revocation and review someone else's request. Each approved decision writes an immutable revision linked to its change request with an audit entry and outbox event. Approval uses the shared change-request engine. Its decision history and version checks reject self-approval and stale review. The shared notification service delivers an in-app update to the requester when a certification or revocation takes effect. The dashboard widget and history exports require current certification. Revocation removes the widget from the available catalogue and disables its data and export routes.

The shared scheduler queues a project lifecycle capture on the first day of each month at 00:05 IST. Company-level pipeline operators can also queue a capture from the page. A capture is one transaction with one record per company, observed month and dataset version. Retries and concurrent requests preserve the first observation. The retained fact grain is one lifecycle observation per project. Capture history shows the latest 24 observed months, counts only projects in the current audience's scope, and verifies stored rows against the refresh record. The timestamp records when the source was read. A successful capture produces an in-app notification for pipeline operators. Missed months remain absent.

CSV, XLSX and PDF history exports use the existing audited export service and intersect project view and export scopes. Pipeline operators can manage captures and view refresh quality without receiving project figures unless they have separate project-view permission. [API contract](../bi-openapi.yaml)

The catalogue also shows project-level SPI and CPI from approved Site Progress period closes, EAC from approved Finance forecasts, and gross margin from approved, frozen Finance P&L snapshots. Each definition identifies its owner, formula, refresh cadence, source register and dataset version. Project selection and values require catalogue and source permissions for the project. CPI additionally requires access to Site Progress cost data. Gross margin requires the Finance P&L and snapshot view permissions. Missing denominators are shown as unavailable. Source links point to the record and revision used.

The same scheduled job captures the enabled source metrics separately by company, metric, dataset version, project and observed month. Historical values retain their source period and revision after owner records are amended. Quality checks compare the recorded source and null counts with the retained facts. The pipeline operator sees freshness and missing-value counts without seeing project values. A capture can be complete for the received source rows even when some projects have no eligible source record.

Each metric has an independent certification and revocation history. The shared dashboard exposes a metric only after certification and applies the selected project's source scope. Project 360 uses the live approved value for the current month and looks up retained captures for earlier months. Both consumers link to the underlying source record. Certified metric histories export to CSV, XLSX and PDF through the audited service. Standalone history exports and figures included in Project 360 exports also require the source's export permission for the project.

The catalogue covers all seven KPIs named in the brief. DSO uses approved invoices, posted open balances and the Finance sales window. Stock turns uses the issues and average inventory valuation of the project's active stores over 90 days. LTIFR uses HSE incident classifications and recorded hours over the configured HSE window. These three values link to their project-filtered reports. The snapshots retain the source project, observed date and calculation version. DSO is an observed value and relies on the balances available when the source is read.

Stock turns and LTIFR use project-wide observations. The reader must hold the necessary source scopes across the project's sites. When preparing or downloading a queued export, the shared exporter now rechecks the saved project against current permissions and certification state.
