## 2. What was built

**Page** `/bi/control-tower` (menu: **Reports → Enterprise Control Tower**; **Executive Alerts** opens the same page on its worklist). It is an overview page with four pill tabs:

- **Executive dashboard**: the hero KPI comes first (portfolio EAC), followed by revenue to date, gross margin, SPI, CPI, DSO, LTIFR and stock turns. Each tile shows its value, its trend against last month's capture, its target where a rule sets one and a status colour. It also shows whether the metric is certified and how many projects it covers. Money is shortened to lakh or crore, with the exact value on hover and in the drill-down. The other cards are portfolio health by dimension (a chart where each bar opens the matching projects), executive alerts, my pending actions, the cash outlook from the published 13-week forecast, and metrics awaiting certification. The subtitle shows when the certified metrics were evaluated and when the last monthly capture ran (BR-01).
- **Health matrix**: RAG for each project on time, cost, quality, safety and cash, plus overall. It can be filtered by region, sector, project manager, RAG and dimension, and sorted by any metric. It is paginated on the server. On a phone it shows as cards. Each figure links to its source record. Opening a project shows its certified metrics with source records and earlier observations, the WBS rows of the approved progress period behind its SPI, its active alerts and a link to Project 360 (FR-04).
- **Executive alerts**: a worklist filtered by status, severity, rule, project and "only mine". From here an alert can be acknowledged, or resolved with a note. Each alert links to its task and its source record.
- **Early-warning settings**: the rules in force. A change is proposed with a reason and approved by a director or the CFO, never by the person who proposed it. The decision history is shown.

**Early-warning rules (FR-03)**:

| Rule | What triggers it |
|---|---|
| `SPI_LOW` | SPI below the threshold for N periods (from the live value and earlier captures) |
| `CPI_LOW` | The same test on CPI (added so that the cost RAG can be configured) |
| `EAC_GROWTH` | EAC growth above x % |
| `COLLECTIONS_OVERDUE` | DSO above y days |
| `CASH_NEGATIVE` | The published 13-week forecast drops below the threshold (company level) |
| `LTI` | LTIFR above the threshold |
| `MATERIAL_SHORTAGE` | Late MRP shortages |

The rules run in three ways:

- as a daily job at 05:45 IST, before the morning report;
- on demand (**Run checks now**);
- as soon as the `fin.cash_forecast.published`, `proc.mrp.shortages_found` and `proc.mrp.run_completed` events arrive.

When a rule is breached, the tower handles it as follows:

- It raises one `exec_alerts` row with an owner: the PM, else the project director, else a PD, or for a company-level alert the CFO, else a director.
- It creates a task for the owner (04.08).
- It sends an in-app notification to the owner, and also to directors when the alert is critical (04.06).
- It publishes `bi.exec_alert.raised` through the outbox and writes an audit entry.

An alert resolves itself, and completes its task, when its condition clears. The same evidence never raises a second alert. A rule whose metric is not certified is skipped and reported; it is never estimated.

**APIs** (documented in [bi-openapi.yaml](../bi-openapi.yaml)):

- `GET /bi/control-tower`
- `GET /bi/control-tower/projects/{id}`
- `GET /bi/control-tower/export` (CSV/XLSX/PDF, audited)
- `GET /bi/exec-alerts`, `GET /bi/exec-alerts/{id}`
- `POST /bi/exec-alerts/{id}/act` (acknowledge or resolve; `version` and Idempotency-Key required)
- `POST /bi/exec-alerts/evaluations`
- `GET /bi/exec-alert-settings`
- `POST /bi/exec-alert-settings/requests` and `…/{id}/act`

**Shared services used**:

- 27.03 catalogue, extended with a bulk reader `readPortfolioMetrics` (one pass per source) and a *revenue to date* definition from the frozen P&L (23.12)
- change-request engine (maker-checker)
- tasks, notifications, audit, outbox, export writer
- Site Progress period service (WBS level)
- widget registry: `bi.exec_alerts` and `bi.revenue_to_date`, plus a Project 360 slot

**Permissions**: `bi.control_tower.view`, `bi.control_tower.export`, `bi.exec_alert.view`, `bi.exec_alert.manage`, `bi.exec_alert.configure`, `bi.exec_alert.run`.

| Role | Grant |
|---|---|
| DIR, CFO | Everything |
| PCMGR | Everything except configure |
| PD | View, export and manage |

Assignments limit each role to its projects. Company-level alerts and the cash outlook need a company-wide grant. Metric values follow each source metric's own permissions, so CPI, margin and stock values are hidden from roles that may not see them.

**Events**:

- `bi.exec_alert.raised`, `bi.exec_alert.acknowledged`, `bi.exec_alert.resolved` (for 27.05)
- `bi.exec_alert.settings_changed`

**Labels** are in English, Hindi and Telugu (i18n area `ct`).

## 7. How to verify manually

1. In a test company, set the flags `ff.bi.p2701`, `ff.bi.p2702`, `ff.bi.p2703`, `ff.bi.p2704`, `ff.site.p1405`, `ff.fin.p2311` and `ff.fin.p2312`, and record the G1 and G2 gates.
2. Approve progress periods, cost forecasts and frozen P&L snapshots for two projects.
3. In **Reports → Metric Catalogue**, a PCMGR requests certification of SPI, CPI, EAC, gross margin and revenue to date, and a CFO approves.
4. Sign in as a director and open **Reports → Enterprise Control Tower**. Check that:
   - the subtitle shows the evaluation and capture times;
   - each tile equals the catalogue value (open the Metric Catalogue to compare);
   - DSO shows "Awaiting certification" until it is certified.
5. Select the hero tile. The health matrix opens. Filter by sector, then by RAG. Open a project, then follow its SPI link to the progress period (the source record) and **Open Project 360**.
6. Select **Run checks now**. After the job runs, **Executive alerts** lists the breaches. Check that:
   - each alert has an owner and a task (the task link opens it);
   - acknowledging an alert works;
   - resolving an alert requires a note.
7. Approve a new progress period with a healthy SPI and run the checks again. The SPI alert resolves itself.
8. In **Early-warning settings**, a director proposes a new DSO threshold. The same director cannot approve it. A second director or the CFO approves it, and the new version shows with its approver. The audit trail holds the old and new values.
9. Sign in as a PD assigned to one project. The tower, the matrix and the alerts show only that project, and the cash outlook says it is for company-level finance roles.
