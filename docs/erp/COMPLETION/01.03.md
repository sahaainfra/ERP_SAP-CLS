## 1. Discovery summary
Nothing for company settings, financial years, numbering, parameters, holidays or approvals existed; only the `company_id` scope column and the role and approval reference documents. Decision per requirement: `docs/erp/DISCOVERY/01.03.md`. Departures from the pack: money stays in minor units (ADR-14), the holiday Excel file is read in the browser (ADR-28), and approvals use a thin stand-in engine (ADR-27, D-022).

## 2. What was built
- **Tables** (migrations `20261030000008` to `20261030000010`, up and down): `core_company_settings`, `core_financial_years`, `core_periods`, `core_parameters`, `core_holiday_calendars`, `core_holidays`, `core_document_types`, `core_number_series`, `core_number_counters`, `core_number_issues`, `core_change_requests`, `core_change_request_steps`, `core_sample_documents`. Flag `ff.core.p0103` (default OFF, ON in development and test) and document type `SAMPLE_DOC` are seeded.
- **Company settings**: legal identity, address, GSTIN per state (check character verified), PAN, CIN, currency, time zone, date and number formats, financial-year start month. Saved with a reason, optimistic locking and audit.
- **Financial years and periods**: a year creates twelve monthly periods with a status per module (Open, Soft-closed, Closed). `assertPeriodOpen` is the call every posting module makes. Reopening a closed period is an approval request (Accounts Manager, then CFO).
- **Numbering**: document type registry; series with tokens `{PREFIX} {BRANCH} {PROJECT} {FY} {FYS} {YYYY} {YY} {MM} {DD} {SEQ:n}`; gap-free issue inside the caller's transaction; reset never, per financial year or per month; project, branch, company precedence; preview from the same formatter; assignment at create, submit or approval; cancelled numbers kept; a change to a series that has issued numbers needs approval (System Administrator, then Accounts Manager for statutory documents). A new integrity check `sequence_gaps` proves gap-free series have no gaps.
- **Parameters**: typed registry (four parameters defined), scope system, company, project and site, effective dates with history, cache emptied on write.
- **Holidays**: calendars per company, state or site; holiday CRUD; Excel (.xlsx) import, all or nothing; `isHoliday` and `isWorkingDay`.
- **Pages** (behind `ff.core.p0103`): Company Settings, Financial Years & Periods, Document Types & Numbering (live preview), System Parameters, Holiday Calendars. The development role bar now offers Accounts Manager and CFO.
- Docs updated: `ARCHITECTURE.md` (section 12), `DECISIONS.md` (ADR-23 to ADR-28), `DEFECTS.md` (D-022 to D-025), `DB_CHANGES.md`, `DB_BASELINE.md` (regenerated), `openapi.yaml`; `schema/baseline.json` re-locked with the new objects (old objects unchanged).

## 7. How to verify manually
1. `npm install`, `npm run build`, `npm start`, open http://localhost:3000 (flag `ff.core.p0103` is ON outside production).
2. Role SYSADM, Company Settings: enter a bad PAN and save (field error), fix it and save; the change is audited.
3. Financial Years: create 2026-27 (12 open periods). Switch to ACCMGR and soft-close or close a module for a month; Close financial year needs every period closed.
4. As ACCMGR on a closed period: Request reopen. Approve as ACCMGR, then as CFO (the second approval applies it).
5. SYSADM, Numbering: add a series; the example under the format updates as you type and warns when numbers would repeat.
6. Parameters: set a company value from today; History shows the earlier value and the new row.
7. Holidays: add a calendar, add a holiday, try the same date twice (refused), import an .xlsx with columns Date, Name, Type.
8. `NODE_ENV=test node --test tests/numbering.test.js` runs the 100-parallel and multi-process proofs; `npm run erp:regression` runs everything.
