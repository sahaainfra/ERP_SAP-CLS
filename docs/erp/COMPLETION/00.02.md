## 2. What was built
- **Tables** (migrations up and down): `core_feature_flags`, `core_audit_log`, `core_outbox`, plus the reference seed for `ff.prog.p0001` and `ff.prog.p0002`.
- **API**: `GET /api/v1/core/feature-flags`, `PATCH /api/v1/core/feature-flags/:key` (reason required, version checked), `GET /api/v1/core/feature-flags/evaluate`, `GET /api/v1/core/session`, `GET /api/health`. Documented in `docs/erp/openapi.yaml`.
- **Service**: precedence project, company, environment, flag default; each change writes its audit row and outbox event `core.feature_flag.changed` in one transaction.
- **Page**: Feature Flags (Administration > System): list with search and paging, toggle with reason, add override, CSV export, skeleton, empty, error (with correlation ID) and no-permission states, light, dark and high-contrast themes, phone card layout, dates as DD-MMM-YYYY in IST. The `useFeatureFlag` hook updates the page at once after a change.
- **Permissions**: `core.flag.view` (SYSADM, ITADM), `core.flag.configure` (SYSADM); evaluate is open to any signed-in user for their own company. Company-scoped queries; other companies' overrides are never listed or changeable.
- **Tooling**: start-up config validation, demo-seed guard, schema-diff with a locked baseline, golden-output harness with approval lines in DECISIONS.md, `npm run erp:regression` with HTML and JSON report, ESLint, non-strict `checkJs`, EditorConfig, PR template with the Definition of Done, commit convention.
- No workflows or notifications: none apply (see defect D-002).

## 7. How to verify manually
1. `npm install`, copy `.env.example` to `.env`, `npm run build`, `npm start`; open http://localhost:3000.
2. As SYSADM, company 1: see six flag rows; the chip says ff.prog.p0002 is ON for your company.
3. Click "Add override", choose ff.prog.p0002, level Company, company 1, leave Enabled unticked, enter a reason, save. The chip turns OFF at once; reload and it stays OFF.
4. Click the switch on that company row, enter a reason, confirm. The chip returns to ON.
5. Switch the role bar to ITADM: rows visible, switches disabled. Switch to PM: no-permission message.
6. Set company to 2 as SYSADM: company 1's override is not listed.
7. Run `npm run erp:regression` and open the report.
