- **Permissions**: `sec.policy.view`, `sec.policy.edit`, `sec.device.manage`, `sec.licence.view`, `sec.licence.edit` (SYSADM all; ITADM view and device revocation; AUD and DIR view). Starting a secure conversation is by the policy's role list.

## 7. How to verify manually
1. As the system administrator open **Administration, Open-Source Licence Register**: the gate says "not approved". Choose **Send the review for approval**; the IT administrator and then the director approve it in their approvals inbox. libsignal shows "Not allowed", the platform library "Approved".
2. Open **Secure Messaging Policy**, switch secure messaging on, set the roles, give a reason; a second person (IT administrator) approves.
3. Each person opens **Safety Number Verification** once and chooses **Set up secure messaging on this device**. In **Messages, New** choose **A secure conversation**, pick the person, **Start**, write a message and attach a file.
4. The other person sees the lock in the list, opens it and reads the text and downloads the file. Open **Safety number** on both screens: the 60 digits are the same; **Mark as verified**.
5. The other person sets up a second device (another browser): the first person's next message is held behind "The safety number changed"; accept, and both devices receive it.
6. Revoke a device under Safety Number Verification (or as the IT administrator under Secure Messaging Policy): it can no longer receive.
