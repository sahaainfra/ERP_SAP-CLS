## 1. Discovery summary
No file handling existed. Decision per requirement: `docs/erp/DISCOVERY/01.05.md`. Departures from the pack: local-disk storage only (S3-compatible adapter not built, D-033); thumbnails for images only (D-034); no ClamAV is installed here, so the built-in scanner finds test signatures only (D-031); `core_files` gained category, version chain, retention class and scan detail, and two more tables hold upload sessions and per-company settings.

## 2. What was built
- **Tables** (migrations `20261030000014` and `20261030000015`, up and down): `core_files`, `core_file_uploads`, `core_file_settings`; flag `ff.core.p0105` (default OFF, ON in development and test). New dependencies: `busboy` (multipart) and `sharp` (thumbnails).
- **Storage** (`platform/files`): a storage adapter contract with a local-disk implementation outside the web root, one folder per company, validated keys; quarantine area; temporary upload area.
- **Checks**: extension allow-list and magic-number match for 19 file types; Windows, Linux and macOS programs and scripts refused under any name; size limit per category; empty files refused; duplicate content on the same record refused (409).
- **Uploads**: one multipart request for small files; resumable chunked upload (start, append at offset, complete) for large ones, where a half-received chunk counts for nothing and completing twice returns the same file.
- **Scan and thumbnails**: background job `core.file_scan` runs the scanners (built-in test-signature scanner; ClamAV through clamd when `CLAMAV_HOST` is set). Infected files are moved to quarantine and never served; a scan that cannot decide is retried five times, then marked ERROR and can be scanned again by an administrator. Clean images get a 256 px WebP thumbnail.
- **Metadata**: name, MIME, size, SHA-256, uploader, time, linked record, version chain; capture time and GPS read from photos; optional stripping of all other metadata from JPEG and PNG.
- **Download**: `GET /files/:id/url` checks view permission on the linked record and CLEAN status and returns an HMAC-signed link (life 30 to 3600 s, default 120 s, a company setting); the content route verifies the signature, honours byte ranges, sets the content type from the validated type, `nosniff`, a restrictive CSP and `attachment` for non-previewable types.
- **Access follows the record**: modules register record types (`fileEntities`); the file service asks the owning module whether the caller may view or edit and whether the record is locked. `sample_document` is registered. Deleting is a soft delete; a locked (submitted) record keeps its files and gets new versions instead.
- **Settings**: allowed types, size limits, retention class per category, link life; changed only through a maker-checker request (System Administrator asks, IT Administrator approves).
- **Pages** (behind `ff.core.p0105`): File Storage Settings (scan status tiles, scanner warning, by-category usage, files needing attention with Scan again, current settings, request a change, request history with approve and reject, export) and Sample Documents (a reference record page hosting the upload component). The upload component offers drag and drop, Choose files, Take photo (rear camera on phones), progress, cancel, retry that resumes the same session, scan status, preview thumbnails, Open and Download through signed links, New version and Remove with a reason.
- Docs updated: `ARCHITECTURE.md` (section 14), `DECISIONS.md` (ADR-35 to ADR-41), `DEFECTS.md` (D-031 to D-037), `DB_CHANGES.md`, `DB_BASELINE.md` (regenerated), `openapi.yaml`, `.env.example` (`FILE_URL_SECRET`, `CLAMAV_HOST`, `CLAMAV_PORT`); `FILE_URL_SECRET` is required in staging and production; `schema/baseline.json` re-locked with the new objects.

## 6. Known limitations / deferred items
D-031 (no real anti-virus connected: the most important one before real use), D-032 (EICAR on disk), D-033 (no S3 adapter), D-034 (no PDF thumbnails or video posters), D-035 (only the sample document takes attachments), D-036 (retention classes are recorded but nothing purges; settings have no effective dates and cannot be imported), D-037 (a signed link is a bearer until it expires). The log of one earlier finding: opening a file in a new tab must be done synchronously on the click or the browser blocks it; the component does this.

## 7. How to verify manually
1. `npm install`, `npm run build`, `npm start`, open http://localhost:3000 (flag `ff.core.p0105` is ON outside production). Create a financial year and a numbering series for `SAMPLE_DOC` first (Financial Years, Numbering pages).
2. Role PM, Sample Documents: create a document. Drag a PDF and a photo into the box, or use Take photo on a phone. Each shows "Scanning..." then "Clean"; the photo shows a thumbnail. Open and Download use a link that stops working after about two minutes.
3. Try a program renamed to `.pdf`, or an `.exe`: the upload is refused with a clear message. Try a file with the text `ERP-TEST-VIRUS-SIGNATURE-1b6f1c52-DO-NOT-STORE` in a `.txt`: it shows "Quarantined" and cannot be opened.
4. Upload a file larger than 5 MB: it goes up in chunks. Turn the network off mid-way (browser dev tools) and back on, press Retry: it continues where it stopped.
5. New version replaces a file (shows v2 and "replaced" on the old one). Submit the document: Remove is disabled (the record is approved) but New version still works.
6. Role SYSADM, File Storage: tiles show the scan counts; the quarantined file is listed with Scan again where it applies; the warning says only the built-in scanner is active. Request a change (for example a document limit of 77 MB); switch to ITADM and Approve: the limit updates.
7. `NODE_ENV=test node --test tests/files.test.js tests/upload-client.test.js` runs the proofs for T-01 to T-04; `npm run erp:regression` runs everything.
