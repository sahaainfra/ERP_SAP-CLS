## 1. Discovery summary
The server was flat files with routes, validation and rules mixed in `app.js`. Table of decisions per requirement: `docs/erp/DISCOVERY/01.01.md`. The only legacy code is this repository's own parts 00.02 and 00.03; its routes are protected by a recorded contract snapshot.

## 2. What was built
- **Structure**: `src/server/platform/{config,db,http,auth,validation,pagination,money,health,audit,events}` and `src/server/modules/core` (routes, controller, service, repository, validators per resource) as the reference module; `modules/registry.js`; client `platform/{api,query,shell}` and `modules/core`. Reference text: `docs/erp/ARCHITECTURE.md` (checked by tests against the real folders).
- **Pipeline**: correlation ID (accept or generate), security headers, one JSON log line per request (no query string or body), 50 KB body limit, JSON parsing, standard error envelope with one error-code registry (11 codes). Bad JSON is now 400 `BAD_JSON` and an oversized body 413; both were 500 before (ADR-04).
- **Validation, lists**: `parse` (field-level details) and `parseListQuery` (`page`, `pageSize` max 200, `sort`, `q`, `filter[...]`, `from`, `to`, allow-lists); the flag list uses them and now also sorts and filters.
- **Base helpers**: optimistic update and version check, soft delete (DRAFT only), standard-column fill, audit writer, transactional outbox writer with the standard event envelope.
- **Decimals**: exact BigInt decimals, money 2 / rate 4 / quantity 3 / percent 4, half-up rounding, `allocate`, INR formatting with lakh and crore grouping, IST dates, financial year; shared by server and browser.
- **Health**: `GET /health/live` (public), `GET /health/ready` (ITADM/SYSADM or monitoring token; database, queue, storage; 503 on failure, `degraded` for a backed-up outbox). `/api/health` unchanged.
- **Frontend**: one API client (auth headers, correlation ID, `ApiError`, GET retry with back-off), TanStack Query with a key factory, module route registry, navigation hidden by permission and by flag. Flags and About pages moved onto it.
- **Page**: Administration > Architecture (Technical Console): guide rendered from the markdown, table of contents, live module map, filterable and CSV-exportable error-code table, pagination contract. Permission `core.arch.view` (SYSADM, ITADM); behind `ff.core.p0101` (migration `20261030000005`).
- No tables or columns added. No workflows.

## 7. How to verify manually
1. `npm install`, copy `.env.example` to `.env`, `npm run build`, `npm start`, open http://localhost:3000.
2. As SYSADM click Architecture: read the sections, use the table of contents, filter the error-code table with `409`, press Export CSV.
3. Switch the role bar to PM: the Architecture, About and Feature Flags links disappear and the page shows the no-access message.
4. In Feature Flags, add a company override turning `ff.core.p0101` OFF for your company: the Architecture link disappears and the page says it is not enabled.
5. `curl http://localhost:3000/health/live` returns `{"status":"ok"}`; `curl -H "x-erp-user: a" -H "x-erp-roles: ITADM" http://localhost:3000/health/ready` shows the three checks.
6. Stop the database to see 503: run the server with a database path in a folder, delete or lock the file, or run `NODE_ENV=test node --test tests/health.test.js`.
7. `curl -X POST -H "content-type: application/json" -d "{bad" -H "x-erp-user: a" http://localhost:3000/api/v1/core/feature-flags` returns a 400 `BAD_JSON` envelope with a correlation ID.
8. `npm run erp:regression` and open the report.
