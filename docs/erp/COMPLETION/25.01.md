# Part 25.01 — Portal Framework, External Identity, Isolation & Branding

Date 2026-11-20. Build is the local working tree. Status is in progress pending production acceptance.

## 1. Discovery summary

The security pipeline, business partner master, Programme Gates and project stakeholder register are implemented. Portal accounts reuse active partner contacts and project stakeholders. Vendor registration goes through the existing MDM activation workflow. The development database had one company and no G1/G2 sign-offs. See [discovery and references](../DISCOVERY/25.01.md).

## 2. What was built

- The separate portal entry supports invitation activation, Argon2id passwords, authenticator codes with replay protection, lockout, terms acceptance and expiring sessions. Each authenticated request checks the current contact or stakeholder and company gate state.
- PROCMGR, COMMGR and scoped PM users can invite eligible contacts. SYSADM can search, filter, save views, choose columns, export and revoke accounts in Portal Users. Revocation clears credentials and sessions.
- Prospective vendors submit to the existing PROCMGR → ACCMGR activation workflow. A private receipt gives access to the registration status and a returned registration. Partner activation and portal invitation are separate actions.
- The external shell shows company branding, profile, inbox, profile requests, and shared documents. Common field labels are available in English, Hindi and Telugu. Theme and text-size controls use the existing design tokens.
- A portal administrator who owns or manages a document can share its current clean issued revision with an eligible account. Download uses a 60-second signed ticket bound to the portal session and revision, rechecks scope and revision status, and adds a recipient watermark.
- The account lifecycle and portal actions use the shared audit trail and transactional outbox. The route registry requires a partner scope declaration on external portal routes. [Portal OpenAPI](../portal-openapi.yaml)

## 7. How to verify manually

1. Check G1 and G2 under Administration → Programme Gates for the target company. The existing ITADM → DIR workflow owns the sign-offs.
2. In a test company with both gates signed and the portal flag enabled, open Administration → Invite portal user using an authorized role. Select an eligible contact or stakeholder and send the one-time link to the contact.
3. Open the link in a separate browser context. Enroll the authenticator, set a password, accept the terms and sign in with the next code. Open My company, request a change and find the request in Inbox.
4. Open Administration → Portal Users as SYSADM and manage the account. Send a notice or close a profile request with a response. Share an issued document revision using an account that owns or manages that document.
5. Read the notice and download the document from the portal. Revoke access in Portal Users and try another portal action to verify the session is refused.
6. Open Register as a vendor in a separate context, submit and retain the receipt. Return or approve the record in the ERP approvals inbox as procurement and then accounts. Check the registration status using the receipt after each decision.
