# Part 04.07 completion: Communication Gateway: E-mail, SMS, WhatsApp, Push and OTP

Status: **Ready for review, with the open items below** (SMTP, SES, FCM and voice codes, other operators' receipt formats, an inbound mailbox, the operator-side DLT check, the translation of the pages and a shared pace counter are later: D-212 to D-217). Feature flag `ff.eng.p0407` (OFF by default; ON in development and test).

## What was found
The integration hub (01.08) already had connectors, a rate limit, a breaker, retries and a signed webhook endpoint, but only a sandbox and a generic HTTP provider, and it knew nothing about consent, DLT or conversations. The notification engine (04.06) called the connectors directly, and sign-in MFA (02.01) kept its own code. Nothing recorded a message, tried a second connector, checked a registered text-message template or linked a reply to a record.

## What was built
- **Database** (migrations 68 and 69; nothing existing altered): `comm_messages`, `comm_consents`, `comm_otps`, `comm_channels`, `comm_dlt_templates`, `comm_wa_templates`; reference seed: the flag, the verification-code template in English and Hindi for five channels, three navigation entries and tracker rows.
- **Providers** (`platform/comm/providers.js`): SendGrid for e-mail; a sandbox for e-mail, text message and WhatsApp that keeps what it was given and can simulate an outage or a refusal; a generic Indian text-message API carrying the DLT identities; the WhatsApp Cloud API with approved templates, session text and documents.
- **The gateway** (`platform/comm`, ADR-184 to 188): checks and queues or blocks with a reason; a queue with priority, a pace per channel and retries (1, 5, 30, 120 minutes); failover from the first to the second connector with the trail kept; consent (opt-in for commercial messages, STOP and START keywords, essential messages not stopped by an opt-out); DLT pattern match for text messages; approved template or 24-hour session for WhatsApp; delivery receipts that only move a status forward; inbound replies linked to the conversation of the record.
- **One-time codes** (BR-02): six digits, only an HMAC kept, five minutes, five tries then locked, a wait before a resend, a limit per hour, redacted in the log, never returned by an endpoint. Sign-in MFA now uses this service.
- **Notification engine**: with the flag on, e-mail, SMS and WhatsApp notifications go through the gateway; the delivery log follows the receipts.
- **API** (`/api/v1/comm`): messages (list, one with its conversation, summary, export, send again), channels (read, propose a change, sample message, WhatsApp template sync), consents (list, record, import, history), codes (send, verify). Route policy covers 15 routes; writes are audited and need an idempotency key.
- **Pages**: Communication Log `/admin/communication-log` (filters, chart, export, route and reason for each message, conversation, send again), Channel Settings `/admin/communication-channels` (connectors and failover, sender, pace, DLT templates, WhatsApp templates, sample, sent for approval), Consent Register `/admin/communication-consents` (record, import, history).
- **Permissions**: `comm.log.view`, `comm.channel.view`, `comm.channel.edit`, `comm.consent.view`, `comm.consent.edit`. Parameters: `comm.max_attempts`, `comm.otp.resend_seconds`, `comm.otp.max_per_hour`, `comm.otp.max_attempts`, `comm.retention_days`. Jobs: `comm.dispatch` (every minute), `comm.purge` (02:10).
- Documents: ARCHITECTURE section 41, DB_CHANGES, DB_BASELINE, the schema lock, DECISIONS (ADR-184 to 188), DEFECTS (D-212 to D-217), PROGRESS.csv (row 35). The OpenAPI file does not list the engines' routes (04.06 and 04.05 are not in it either); the route policy is the registry.

## Click-path for a reviewer
1. As the IT administrator open **Connectors** and create sandbox connectors (one text-message connector set to simulate an outage, one working). Open **Channel Settings**: choose the first and second connector for text messages, the sender ID, add a DLT template for `ntf.test` (`Test notification {#var#}`), give a reason, **Send for approval**. The page says a change is waiting; the settings in force are unchanged.
2. As the system administrator approve it in **My Approvals**. Reload Channel Settings: the new order is in force.
3. **Send sample** by e-mail (arrives); by text message: the **Communication Log** shows it Sent by the second connector, and its route lists the first as failed.
4. Change the DLT text so it no longer matches and send a sample: the log shows **Blocked** with "does not match the DLT template".
5. **Consent Register**: record an opt-out; the history shows who and when. A commercial message to that number is blocked; a verification code is not.
6. As a person without the permission the three pages say so and name the permission.

## Tests and acceptance
- **T-01** the primary text-message connector is down: the second delivers, the log shows both attempts and the sandbox received one message. **T-02** a text that does not match its DLT template is blocked (`DLT_MISMATCH`), one without a template too (`DLT_NO_TEMPLATE`), and nothing reaches a provider. **T-03** an inbound WhatsApp reply (signed webhook) joins the conversation of the RFQ it answers; a late "delivered" receipt does not undo "read".
- Also in `tests/communication.test.js` (10 tests): STOP and START, commercial messages need an opt-in, essential messages still go, history, import; codes (hash only, redacted log, a code works once, another person cannot try it, lock after the tries, expiry, resend too soon 429); channel changes (one at a time, bad connectors and types refused, what is in force stays until approved, off blocks); send again; urgent first; permissions (200 / 403 / 401). The MFA tests of sign-in still pass with the new service. Browser: `e2e/communication.spec.js` (4 runs, desktop and phone width).
- **AC-01** channels with failover and the log. **AC-02** DLT block. **AC-03** codes. **AC-04** consent and STOP. **AC-05** a change of channels is a maker-checker document and an audit entry. **AC-06** page checks and permission messages. **AC-07** this report.
