# Part 04.01 completion: workflow engine core: definitions, instances, states and tasks

Status: **Ready for review, with the open items below** (the approval matrix, notification delivery, the task inbox page and the other request types are later parts: D-173 to D-181). Feature flag `ff.eng.p0401` (OFF by default, ON in development and test); the adapter flag `ff.eng.p0401.legacy.ui_translation_change` moves the wording requests of part 03.09 onto the engine.

## What was found
There was no workflow engine. The only approval code was the stand-in of part 01.03 (`platform/approvals`, D-022): a flat chain of roles on `core_change_requests`, used by 18 request types. It has no delegation, parallel steps, clarification, SLA, versioned definitions or amendment. It stays, behind an adapter (ADR-157), and is replaced one request type at a time. See `docs/erp/DISCOVERY/04.01.md`.

## What was built
- **Database** (migrations 56 and 57; nothing existing altered, schema-diff of the 402 locked objects empty): `wf_definitions`, `wf_instances`, `wf_tasks`, `wf_task_attachments`, `wf_history` (append-only, guarded by triggers), `wf_watchers`, `eng_sample_docs`; the flags, three navigation entries and five tracker rows.
- **Engine** (`platform/workflow`): document-type registry with hooks that run in the decision's transaction, resolvers, system actions; definitions with versions, step kinds (approval, review, notification, system action), modes (single, parallel-all, parallel-any), approvers (role in the project or site, `A|B` alternatives, person, reporting manager, resolver), required attachment, checklist, SLA, conditions; submit, act (approve, reject, return to the originator or an earlier step, clarify and answer, delegate), withdraw, cancel, resubmit into the next round, amendment link, watchers, the administrators' queue, SLA reminders and escalations (job every 15 minutes), `isLocked`.
- **API** (`/api/v1/workflow/*`, 24 routes, and `/api/v1/eng/sample-docs`, 6 routes; route policy, OpenAPI, `Idempotency-Key` required on submit, act, withdraw, cancel, resubmit and activate; consistent error envelope; optimistic locking on tasks and definitions).
- **Activation of a definition is an approval** (`WF_DEFINITION`: SYSADM, the owner of the process, ITADM), so one person cannot change a chain; its own default is seeded the same way as any module's.
- **Legacy adapter** (`platform/workflow/legacy.js`): a request type whose flag is ON is decided by the engine and mirrored on its request row; `ui_translation_change` migrated (AC-02).
- **Pages** (module `eng`, all behind the flag): Workflow Definitions (list: filters, statuses, pagination, new version), Workflow Definition Editor (form: step list, approver rules, SLA, required items, condition, diagram preview, comparison with another version, save draft, request activation, delete draft), Workflow Instance (object page: header and actions, tabs Steps and tasks, Timeline, Attachments, Related, Details; the decision forms), Workflow Monitor (report: parameter panel, chart, table with totals, needing attention, XLSX and CSV), Sample Documents (the reference document type: draft, submit, locked, amend). The task inbox data is in My Work (a `workSources` provider) and the bell.
- **Permissions** `eng.workflow.view|define|cancel|admin`, `eng.sample.use` with the grants in ARCHITECTURE section 35; events `workflow.instance.*`, `workflow.task.*`, `workflow.notification.requested`, `workflow.definition.activated`, `eng.sample_doc.*`; parameters `eng.workflow.default_sla_hours`, `eng.workflow.escalation_hours`.

## Click-path for a reviewer
1. As a project director open **Administration > Sample Documents**, make a document for ₹2,50,000, **Submit for approval**: the Workflow Instance page shows two steps (the CFO's third step needs ₹10,00,000 or more) and says you cannot decide on your own document.
2. As a project manager open the same address: **Approve**; as an accounts manager **Approve**: the document is Approved and locked (no Edit button), the timeline shows every round. **Amend** makes a new linked document; its approval's Related tab links back.
3. Raise another, ask a question as the manager (the task stays open, approving waits), answer as the originator, **Return**, edit, **Resubmit**: the timeline keeps both rounds.
4. As a system administrator open **Workflow Definitions**, make a new version of the sample document, remove the CFO step, add a store check, see the diagram change, **Save and request activation**. A second system administrator, the process owner (PROCMGR) and the IT administrator approve in turn; the version becomes Active and a document already in approval keeps version 1.
5. Make a definition whose step is "the reporting manager" for a person nobody manages: the document waits in **Workflow Monitor > Needing attention**; an administrator **Assigns** it; nothing was approved on its own.
6. Turn the adapter flag off and on for `ui_translation_change`: the same wording request ends the same way (`tests/workflow-adapter.test.js` does it for approve, reject, return, resubmit, withdraw, the refusals and the in-force text).

## Tests and acceptance
- **T-01** two-level sequential approval completes, locks the document, tells the module (`tests/workflow-engine.test.js`). **T-02** parallel-all waits for both; parallel-any completes on the first. **T-03** return and resubmit keep the history, return to an earlier step, withdrawal works only before the first action. **T-04** a new version leaves a running instance alone (the instance carries its own copy of the steps). **T-05** nobody eligible: the administrators' queue with an alert, never an approval.
- Standard set: API validation, 400/403/404/409/422, idempotent replay, cross-company and cross-project isolation in sign-in mode (`tests/workflow-scope.test.js`), self-approval blocked, one person one step, delegation, escalation, clarification, attachments and checklist, system and notification steps, amendment, export; the adapter test; 3 e2e specs per page at desktop and the phone (`e2e/workflow.spec.js`).
- **AC-01** every action path of the sample document with events and history: the engine test and the browser test. **AC-02** a legacy approval through the adapter with identical outcomes. **AC-03** the five pages pass the page checks (`e2e/pages.spec.js`) and have no placeholder text. **AC-04** `tests/workflow-engine.test.js`, `tests/workflow-scope.test.js`. **AC-05** the sample document's status is written only by the hooks; no route sets it; a definition can only become active through its own approval. **AC-06** see Results. **AC-07** this report.
