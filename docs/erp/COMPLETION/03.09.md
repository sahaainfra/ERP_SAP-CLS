# Part 03.09 completion: localisation (English/Hindi), Indian formats and accessibility

Status: **Ready for review, with the open items below.** Feature flag `ff.ui.p0309` (OFF by default, ON in development and test; with it OFF the bundled English and Hindi and the Indian defaults still apply).

## What was built
- **Catalogue and translator** (`src/shared/i18n`): text by area (`common`, `shell`, `palette`, `field`, `format`, `notify`) and key, in `locales/en.js` and `hi.js`; `{placeholders}`, plural forms, English fallback and a report of missing keys. No library was added (ADR-146). The same files serve the browser and the server.
- **Screens moved to the catalogue:** the shell (header, menus, favourites, breadcrumbs, guards, bottom bar), the command palette and shortcut list, the feedback states (loading, empty, error, no permission), the pager, Field Home, Scan and the scanner, the device menu, the install banners and the location notice. A language switch (per person, saved on the server as before) changes all of them at once; names of menu groups and field tiles come from the registry's Hindi labels.
- **Formats** (`shared/i18n/format.js`): money with Indian or international grouping (₹ 12,34,56,789.00), lakh/crore abbreviations (₹ 1.25 Cr, ₹ 12.50 L; M and K for international), quantities with their unit, percentages, DD-MMM-YYYY dates (Hindi month names in Hindi), 24- or 12-hour time in IST. A person chooses grouping and hour format in My Profile (examples shown before saving; `ui_locale_preferences`); the company default is the parameters `ui.locale.number_style` and `ui.locale.time_format`. Dates on every page follow the language and hour format; dashboard money figures show lakh/crore with the whole amount in the tooltip and for screen readers.
- **Amount in words** (`shared/i18n/words.js`): Indian places (crore, lakh, thousand), rupees and paise, negative, English and Hindi; printed on the sample request (English, D-164).
- **Translation management:** `ui_translations` (a company's own wording over the built-in text); `GET /ui/translations/:lang/:namespace` for every signed-in person; the Translations page (`/admin/translations`, `ui.translation.manage`, system administrator): search by key or word, filters for area and "missing in Hindi", edit English and Hindi, history of a text, coverage line, export of every text as .xlsx, import of the translated .xlsx (a preview with problems per row, then one request for the whole file), pending requests with approve and reject. A change is a request that another system administrator approves, audited with old and new text (event `ui.translation.changed`); placeholders must match the English; "back to the standard wording" removes an override.
- **Messages in the recipient's language:** the unusual sign-in alert, reset code, verification code, sign-in code and invitation are `notify` templates rendered in the recipient's saved language (then the profile language), with the company's wording (`platform/i18n`).
- **No text in components (BR-01):** `eslint-rules/no-hardcoded-text.js` on the moved files; `tests/i18n-lint.test.js` also checks that every key those files ask for exists in both languages and that every key of the field area is used.
- **Accessibility (FR-05, FR-06):** `e2e/a11y.spec.js` runs axe-core 4.11.0 (WCAG 2.0/2.1 A and AA) over the form gallery and design-system pages in the light, dark and high-contrast themes, 13 key pages, the open palette and the shortcut list, desktop and phone, and fails on any serious or critical finding. It found and I fixed: unlabelled file inputs (photo, scan), a labelled loading box without a role, the calendar grid without rows, the chart role (an image with focusable marks), the list-resize handle without a value, scrollable code samples without keyboard access, border-colour samples drawn as low-contrast text, and the palette's listbox (buttons inside options, non-option children, an empty listbox). Added: focus returns to the opener when the palette closes, a global reduced-motion rule, an end-to-end check of the focus ring and of reduced motion.
- **Permissions:** `ui.translation.manage` (SYSADM, SUPADM). Choosing a language and a number format needs none.

## Click-path for a reviewer
1. Sign in as a site engineer. Open **Field Home**; in the account menu choose **हिन्दी**: the heading, status lines, tiles, location notice, skip link and search button turn Hindi. Press Ctrl+K and type nonsense: the message is Hindi. Open **Scan** (`/field/scan`): Hindi. Open a page you may not use: the no-permission text is Hindi. Switch back to English.
2. As a system administrator open **Translations**: search `field.title`, choose **Change**, write a different Hindi text and a reason, **Request change**. Sign in as a second system administrator, open Translations and **Approve**. Reload as the site engineer in Hindi: the new text is shown. Open the text again: its history shows who, when, old and new. Choose **Back to standard Hindi**.
3. **Export for translators**, change a Hindi cell in the file, **Import translated file**: the preview says how many texts change and lists problems by row (a lost `{placeholder}` is refused); give a reason to send it as one request.
4. In **My Profile** under *Number and time format* choose international grouping and 12-hour time: the examples change before you save; save; reload: kept. Choose "Use my company's setting" to return.
5. On **My Work**, a money figure of a lakh or more shows as ₹ 2.32 L with the whole amount on hover.
6. Print a submitted sample request: the footer carries "Amount in words".
7. Run `npx playwright test e2e/a11y.spec.js`: zero serious or critical findings.

Causes, all fixed or explained: two dashboard specs looked for the chart role `img` (the role is `group` now; selector changed); a dead letter of my search index (a bill of a test company with no organisation row broke a foreign key) turned the data-health, operations-health and replay specs red and was found by them: the index carries no company foreign key now (ADR-152, test added); the file specs failed on a repeated company set-up in the same database after those events; one search-admin spec had an ambiguous text match (fixed). After the fixes the dashboard, data-health, files, operations-health, operations and search specs pass again (64 of 64 on both viewports). The sign-in "My Sessions & Devices" spec timed out in the whole run on both viewports and passes when run alone (sign-in is rate limited per minute and address, as its comments say); it was not re-run inside a full run after the fixes. The PWA check passed. The whole suite was not re-run in one piece after the fixes.
- Helpers `e2e/shell-helpers.js` and one assertion in `e2e/shell.spec.js` no longer rely on English labels (the menu, its button and the account menu are named in the language of the screen).
