# Part 26.01 — Testing, Pre-Commissioning & Commissioning

Built 2026-11-25 on the owner's instruction to build module M26 now (audit AUD-DEF-004), which overrides the prerequisite rule for this
module: 18.06 and 11.04 are still awaiting formal acceptance and the development company has no G1/G2 sign-off. The new business routes are
gated by the part flag `ff.close.p2601` only (default off); the earlier evidence adapter keeps its G1/G2 check.

## 1. Discovery summary

[Requirement and service inventory](../DISCOVERY/26.01.md). QA (18.01, 18.06) owns inspections and snags; the shared workflow engine owns
approvals; the file service owns documents. Commissioning owns systems, tags, check sheets, test packs, punch links and certificates.

## 2. What was built

- **Tables** (migration `20261228000430_tnc_commissioning`): `tnc_systems`, `tnc_tags`, `tnc_checksheets`, `tnc_test_packs`,
  `tnc_punch_links`, `tnc_certificates`, with the standard columns, indexes and one open certificate of a kind per system.
- **Server module `close`** (registered in `modules/registry.js`, routes under `/api/v1/close/commissioning`, 15 routes in the route policy):
  - FR-01 systems (with subsystems) and tags; FR-02 check sheets of class A/B/C per tag, passed or failed (a failure needs a note), optionally
    linked to the QA inspection that evidenced them; FR-03 test packs with procedure, witness, date (not in the future) and evidence file;
  - FR-04 punch items: QA snags of the same project linked to the system; their class and status are read live from QA;
  - FR-05 certificates MC, RFC and RFSU: requested by the commissioning lead, approved through the workflow engine (`TNC_CERTIFICATE`: QA/QC
    manager, then project manager, distinct approvers), then the project manager records the client's signatory, date and signed copy
    (the client portal does not take decisions yet, D-761). Issue moves the system to that stage and publishes `tnc.certificate.issued`;
  - FR-06 completion dashboard: per system and in total, check sheets passed by class, open punches, test packs and stages;
  - BR-01 readiness: MC needs every class A sheet passed and no open or rectified class A punch; RFC also class B and an issued MC; RFSU also
    class C, no open class A or B punch, an issued RFC and every test pack passed. Checked at request and again at the client's signature.
- **Permissions**: `tnc.view` (QCE, QCMGR, PM, PD, CM, SE, DIR, AUD), `tnc.manage` and `tnc.test.record` and `tnc.certificate.request`
  (QCE, QCMGR), `tnc.certificate.sign` (PM). Lists are filtered by the project and site scope of `tnc.view`.
- **Pages** (navigation group "Commissioning & Closeout"): Commissioning (dashboard and systems register), the system page (readiness and
  certificate request, tags and check sheets, test packs, punch items), Test Packs, Commissioning Certificates (client signature with the
  signed copy uploaded through the file service). Text in the `close` catalogue area; Hindi and Telugu are drafts that need review.
