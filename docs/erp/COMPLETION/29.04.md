## 2. What was built

The page is `/admin/bulk` (**Administration → Template Packs & Bulk Entry**), with pill tabs:

- **Template packs (FR-01, FR-03)**: five packs: Masters, Workforce, Project data, Rates and SOR, and Business development. For each template a pack shows:
  - its version and who published it;
  - its notes;
  - its templates, with who approves a batch of each (or that each record follows its own approval);
  - **Enter in grid**.

  **Download pack** gives a zip with:
  - a README (version, instructions, templates and history);
  - an instructions workbook listing every column, whether it is required, its type, help and an example;
  - each template the person may import.

  A manager publishes a new version (instructions, examples, the templates it holds, and what changed); the old version is kept in the history.
- **Bulk entry workspace (FR-02)**:
  - Choose a template, then type rows or paste cells copied from Excel. Rows and columns fill from the cell where you paste.
  - After every edit, the rows are checked by the engine's own row check (types, required, lookups, duplicates in the batch and in the data, the module's rules). Each cell in error is outlined in red with the reason, and a list names each row's errors.
  - Drop-downs come from the template; lookups offer the master's codes.
  - **Save draft**, then **Submit** the whole batch with a reason. A batch with any error is refused, with the cells named.
  - On a phone, the page says bulk entry is desk work, and the grid scrolls inside its frame.
- **Batches**: mine, for my approval (including those I have decided) or all (AUD, IT).
  - The module approver approves, returns or rejects; a comment is needed to return or reject.
  - The preparer can never decide.
  - A returned or failed batch can be corrected and submitted again.

**Approval and import (BR-01, section 9)**:

- **Approval-controlled data** (a template whose single records are created directly, such as designations, finance masters or project structure) waits for the module approver. The approver is, for example, HRMGR for designations, CFO for finance masters, PD for project structure, and COMMGR for rates.
- **The import**: on approval the batch is imported as its preparer, through the module's service, after a fresh check, in one savepoint. If anything fails (for example, a code created meanwhile), nothing is saved and the batch is marked **Not imported** with the reason.
- **Own-workflow templates** (drafts, requests, registrations): the rows are imported on submit, and each record enters its own approval.

Labels are en/hi/te (area `bk`).

**Permissions**:

| Role | Grant |
|---|---|
| The modules' data roles | Use the workspace; each template still needs its own import permission |
| AUD, ITADM, SYSADM | See all batches |
| ITADM, SYSADM | Publish pack versions |

T-01:

- **Errors**: five rows return exactly `2:code:FORMAT`, `3:level:RANGE`, `4:code:DUPLICATE_IN_FILE` and `5:code:REQUIRED`. In the browser, the pasted bad code and the out-of-range level are marked `aria-invalid`.
- **Atomic import**: after a second batch is submitted, one of its codes is created by someone else. The approval saves neither row, and the batch is marked FAILED with the reason.

## 6. Known limitations

D-792:

- Only the registered import types are in the packs. Equipment, chart of accounts, cost codes, budgets by project, schedules, opening stock, attendance, MB entries, DPR quantities, journals and opening balances wait for their modules (opening stock and balances: 29.05).
- The module approver is a code table, with one step.
- The grid holds at most 2,000 rows and has no sort or filter.

## 7. How to verify manually

1. In a test company, set `ff.admin.p2904`.
2. As HRMGR, open **Administration → Template Packs & Bulk Entry**, and **Download pack** for Masters. The zip holds the README, the instructions workbook and the Designations template.
3. Under Masters, click **Enter in grid** for Designations. Paste three rows from Excel, one with a bad code; the cell turns red with the reason.
4. Correct it, **Save draft**, give a reason and **Submit for approval**.
5. As another HR manager, under **Batches → For my approval**, **Approve and import**. The designations exist.
