## 1. Discovery summary
There was no form framework: pages built forms by hand from `Field`, `FormDialog` and `errorInfo`, inputs were native, nothing parsed grouped numbers, and there were no drafts, generic lookups, line grid, duplicate checks, "create from", unsaved-changes guard or form definitions. Masters to look up existed for the organisation (projects, sites, cost centres, departments, people), units of measure and holidays; items, vendors and stores (M06) do not exist yet. Decision per requirement: `docs/erp/DISCOVERY/03.02.md`. Departures from the pack: form definitions are code seeded by migration, so the gallery has no edit or approval (ADR-115, D-123); item and vendor lookups and defaults wait for M06 (D-119); offline drafts wait for 04.15 (D-120).

## 2. What was built
- **Field components** (`src/client/platform/forms`): text, number, quantity, currency (₹), percentage, date with a calendar that marks the holidays of the place (`GET /core/holidays`), date range, time, select, searchable server lookup (code, name and extra columns, paged, dependent on a parent), multi-select, checkbox, radio, switch, textarea, restricted rich text (bold, headings and lists in the application's Markdown; no HTML stored), signature pad, GPS position, photo (camera or gallery), QR/barcode (camera where the browser can read codes, from a photo, or typed) and files through the file service. Each has a label, hint, error announced on the field, a disabled state and a read-only state shown as text (BR-03).
- **Number entry (BR-02)**: Indian (12,34,567.50) and international (1,234,567.50) grouping, ₹ and % signs, typed or pasted, kept as plain decimals; grouping that fits neither is refused with a message naming it.
- **Layout (FR-02)**: sections in 1, 2 or 3 columns that fold to one on a phone, collapsible groups, a sticky action bar (Save draft, Save, Submit, Cancel) with the draft status, and an unsaved-changes guard on closing the tab and on moving inside the application.
- **Validation (FR-03)**: one Zod schema shared by the browser and the server (`src/shared/forms/sample-request.js`), an error summary at the top whose lines link to each field (nested grid cells included, "Items, row 3: Quantity"), and the server's 400/422 details placed on the same fields.
- **Context auto-fill (FR-04)**: project and site from the shell's working context, the person, the department from their profile, today's date in India and the financial year; the cost centre defaults to the first one of the chosen site.
- **Dependent lookups and conditional fields (FR-05)**: project, then site, then cost centre; the urgency reason appears only for an urgent request, the return date only for returnable material.
- **Line grid (FR-06)**: add, insert, duplicate and delete rows (selected or current), Enter and the arrow keys move down and up, Enter on the last row adds one, Alt+N inserts, Alt+D duplicates; paste a block copied from Excel (quoted cells, a heading row skipped, at most the grid's limit); unit lookup in the cell; each row's problems on its cells; amount calculated as you type and a totals footer; the first column stays in view; a comment and files for each saved row.
- **Drafts (FR-07)**: kept on the server every 30 seconds while there are changes and when the person leaves a field; offered back when the form opens again (after a closed tab, a crash or on another device); My Drafts lists, resumes and discards them.
- **Duplicate checks (FR-08)**: a registry and `POST /ui/duplicate-check/:name`; checks for people (email, mobile, name), projects (name, code) and sample requests (same title and project within a week). The form warns while typing; it never blocks.
- **Create from (FR-09)**: a registry and `GET /ui/create-from/:target`; a sample material request starts from a sample document, and the request keeps `source_type` and `source_id`.
- **Form definitions (FR-10)**: `ui_form_metadata`, `GET /ui/forms/:code`; the reference form's sections, fields, rules, lookups, conditions and grid are declared once and rendered by `MetaField`.
- **Lookup contract**: `GET /api/v1/<module>/lookups/<name>?q=&page=&pageSize=&parent=&id=`, registered by the owning modules: iam (projects, sites, cost centres, departments, people) and core (units of measure), inside the person's data scope.
- **Reference form (AC-02)**: Sample Material Requests (`/admin/sample-requests`, tables `ui_sample_requests` and `ui_sample_request_lines`): references checked against each other and the person's scope, every line amount from the calculation engine (`boq.line_amount`), a total or amount the screen showed that differs from the server is refused (ADR-118), numbered at submit (document type `SAMPLE_MR`), cancelled requests keep their number, audit and events on every step, the draft consumed when the request is saved.
- **Pages**: Form Components (`/admin/design-system/forms`: 21 components in five states, a live line grid, keyboard reference, the server's forms, lookups, duplicate checks and create-from), My Drafts (`/account/drafts`), Sample Material Requests (list with search, status filter, sort, 25/50/100, CSV export, empty states; the form). Sample Documents has a "Start a material request" link per document.
- **Fixed on the way** (found while taking screenshots): a person in Onboarding could not open Appearance (D-121); four pages showed an error after a successful save (D-122); the no-access message read "the a signed-in account permission".
- Docs: `ARCHITECTURE.md` section 26, `DECISIONS.md` ADR-115 to ADR-118, `DEFECTS.md` D-119 to D-123, `DB_CHANGES.md`, `DB_BASELINE.md`, `openapi.yaml`, route policy (305 routes), `schema/baseline.json` re-locked (316 objects).

Earlier tests changed because the behaviour changed on purpose: the document-type count (`SAMPLE_MR` is seeded), the icon count (six registry icons added), the onboarding gate (`/ui/preferences` is now open to a person without a role, D-121), the migration count, and the data-health test (a document with lines may already exist).
