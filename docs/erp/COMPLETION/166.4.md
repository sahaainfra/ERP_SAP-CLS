## 2. What was built
| Requirement | Where | Notes |
|---|---|---|
| P-02 / FR-01 lazy pages | `platform/shell/lazyPage.js`, `platform/shell/RoutePage.jsx`; the 24 `modules/*/index.js`; `App.jsx` | 624 pages are `lazyPage(() => import('./XPage.jsx'))` (one file holding several pages: by name); the routes stay in the first download. `RoutePage` draws a skeleton while the code arrives and, when it cannot be fetched (offline, or a release removed the old file), "This page could not be opened" with **Reload** (open drafts saved first). The sign-in-link pages, the vendor portal, the verification page and the chat dock are lazy too |
| FR-01 prefetch | `platform/shell/prefetch.js` | with the flag: on Home or the field home, 4 s after it is drawn and when idle, the pages of the person's bottom bar are fetched; never offline or with the browser's data saver. The page being opened is fetched together with the sign-in check (`main.jsx`) |
| P-02b languages | `platform/i18n/index.js` (`loadLanguage`) | English in the first download; Hindi (177 KB gzip) and Telugu fetched for a screen in that language; the screen stays English until they arrive, then draws again |
| P-03 libraries | `vite.config.js` `codeSplitting.groups` | `vendor-react`, `vendor-query`, `vendor-icons` (first download, unchanged across releases); `vendor-xlsx`, `vendor-pdf-lib`, `vendor-qrcode`, `vendor-realtime` with the pages that use them; `pdf.min` and `leaflet` stay split. There is no chart or date library in the client |
| P-04 / T-01 budget | `scripts/bundle_budget.mjs`, `npm run erp:bundle-budget`, stage `bundle-budget` of `erp:regression` | first download ≤ 350 KB gzip, every other chunk ≤ 250 KB (the PDF viewer 400 KB); report per chunk in `reports/bundle-budget.{json,md}` |
| P-05 compression | `vite.config.js` (`precompress`), `platform/http/staticAssets.js`, `platform/http/compressJson.js` | Brotli and gzip copies written at build; `/assets/` sent compressed with `Cache-Control: public, max-age=31536000, immutable`; JSON answers of the API above 1.4 KB compressed. Node's zlib, no new dependency |
| P-06 / FR-02 precache | `vite.config.js` (`shellScripts`, `OFFLINE_PAGES`) | the worker keeps at install the shell and the pages a site person needs with no signal (homes, field home, scan, field forms, sync status, conflicts, phone approvals, DPR entry): 55 of 721 scripts; any other page is kept when first opened |
| FR-02 worker strategies | `src/client/sw.js`, `platform/api/identity.js` (`x-erp-sw`), `platform/device/pwa.js`, `AppShell.jsx` | cache-first for hashed files (kept); with the flag: the shell calls, the field home's counts and the person's queued commands wait at most **3 s** for the network, then the kept copy; the menu is **stale-while-revalidate**, the page is told when it changed and draws it at once |
| P-07 text twice | `modules/ui/translations.js`, `platform/i18n/api.js` | `?only=overrides`: the screens fetch only the company's own wording (empty when it changed nothing) instead of the 489 KB catalogue |
| P-08 first-screen work | `ShellParts.jsx` (`drawOnOpen`), `App.jsx` (`WhenIdle`) | with the flag, on a phone: the menu drawer draws its entries when opened; the chat dock starts when the browser is idle |
| FR-03 low-bandwidth extras | `platform/device/lowBandwidth.js` (`lowBandwidthSaves`), `platform/dashboard/api.js`, `platform/shell/api.js`, `platform/charts/Chart.jsx`, `modules/core/api` (`fetchPhotoUrl`), `modules/site/DprsPage.jsx` | with the flag and the mode on: dashboard widgets and the field home do not refresh by themselves (the refresh button stays); the DPR photo list shows thumbnails, the photo itself when opened; charts are drawn as their tables ("Draw the chart" on request) |
| FR-04 drafts on update | `platform/forms/useDraft.js` (`flushDrafts`), `platform/device/pwa.js`, `PwaBanners.jsx` | with the flag, "A new version is ready — Reload now" saves every open form's changes as a draft first (at most 5 s) and says so; the form offers the draft back after the reload |
