Part: 04.13 Excel Import/Export Engine. Date: 2026-11-04. Feature flag `ff.eng.p0413` (default off; on in development and test).

## 1. Discovery summary
No `xl_*` table existed. Reused: the XLSX/CSV/PDF writers and their formula neutralisation, the XLSX reader, the virus scanner and file store, the job runner, the organisation service (a master adapter), the sample document service (a transactional adapter with an approval chain), the maker-checker pattern, notifications. The existing one-off imports (documents, users, sample documents) are unchanged. Full table in `docs/erp/DISCOVERY/04.13.md`. Prerequisites 03.03 and 04.01 are accepted.

## 2. What was built
- **Database** (migrations 80 and 81, nothing existing altered): `xl_templates` (versions of a company's settings of an import type), `xl_jobs`, `xl_job_errors`; seed: flag, three navigation entries and tracker rows, notification texts in English and Hindi.
- **Engine** (`excel.js`, `xl-xlsx.js`; ADR-207 to 210): `registerImportType` and `registerExportSource` for modules; the template workbook (protected header, required marks, unlocked cells, number and drop-down validation, Instructions sheet, Lists sheet from the masters, hidden sheet with type and version); upload (rights, size, .xlsx, virus scan of the file and every part inside it); the row check (text, whole number, decimal, money, date in several forms, yes/no, list, lookup by code or name, duplicates in the file and in the data, formulas, the module's rules, rights per row); preview with the action of each row and the impact; row-level errors (sheet, row, column, value, reason) and an error file; commit through the owning module's service, all or nothing or in chunks with resume; history; exports of lists and of an import type in template form; template changes by approval.
- **Platform change**: `transaction()` inside a transaction is now a savepoint (ADR-208), so a bulk commit can call module services that have their own transaction.
- **Adapters** (`xl-adapters.js`): Designations (a master created and updated through the organisation service) and Sample documents (created as drafts and sent into their approval chain); export of the import history.
- **API** `/api/v1/xl/*` (14 routes, all in the route policy and `openapi.yaml`): templates, download, export, designer, designer/changes, jobs (upload, list, get, preview, errors, commit, cancel), exports.
- **Pages**: Import Center `/import` (templates, upload, history with filters and export), Import Job `/import/job` (progress, counts, preview, errors, details, commit, cancel, error file), Import Template Designer `/admin/import-templates` (wording, required, chunking, history, pending change).
- **Permissions** `xl.import.use`, `xl.template.view|edit`, `xl.job.view_all`, `org.designation.import`, `eng.sample.import`. **Events** `xl.job.uploaded|validated|committed|failed|cancelled`, `xl.template.changed`; jobs `xl.validate`, `xl.commit`. Documents: ARCHITECTURE section 47, DB_CHANGES, DB_BASELINE, schema lock, DECISIONS (ADR-207 to 210), DEFECTS, openapi, PROGRESS.csv (row 41).

## 7. How to verify manually
1. As the HR manager (or administrator) open **Administration > Import Center**: the imports open to you are listed. **Download template** for Designations: the header is protected, required columns have a *, the Instructions sheet explains the rules.
2. Fill rows, including a repeated code, a code with a symbol and a name that starts with `=`. **Upload and check**: the job shows the counts, the **Preview** says what each row will do, **Errors** lists sheet, row, column, value and reason; **Download the error file** gives your rows with an Errors column.
3. **Commit** is off while rows have errors; tick "import only the correct rows" and commit: the records exist (check Organisation > Designations); the job shows Imported with the counts and appears in the history.
4. Upload the same codes again: they are errors; choose "Update existing records" and the preview says Will update. **Export the data** gives the template filled with the data.
5. As the project manager import **Sample documents**: they are created as drafts or sent into their approval chain, never approved.
6. As the system administrator open **Import Template Designer**, change a label and make a column required, send for approval; as a director approve it under My Approvals; the next template download carries the new wording and version.
