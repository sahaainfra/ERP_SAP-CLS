# DEFECTS

Register of known gaps. Severity: Critical, High, Medium, Low. The scan output of the discovery script is in `docs/erp/DISCOVERY/DEFECTS.md`.

| ID | Area | Description | Severity | Cause | Owning part | Status |
|---|---|---|---|---|---|---|
| D-001 | Auth | Authentication and roles are a development adapter: `AUTH_MODE=dev-headers` trusts `X-Erp-*` request headers, and role permissions are a constant in `src/server/auth.js`. `config.js` refuses it in staging and production, so the app cannot run in production until IAM exists. | High | IAM, roles and permissions tables are parts 02.x | 02.05, 02.07 | Open |
| D-002 | Flags | Flag changes are not maker-checker approved; one SYSADM can change a flag. They are audited (`core_audit_log`) and the reason is mandatory. | Medium | Workflow engine is part 04.01 | 04.01 | Open |
| D-003 | Flags | `company_id` and `project_id` have no foreign keys. | Low | Organisation tables are part 02.02 | 02.02 | Open |
| D-004 | UI | Admin page has English labels only, no Hindi, and is not inside the final application shell or navigation registry. The shell here is a minimal bar. | Low | Design-system shell and i18n are parts 03.x | 03.01 | Open |
| D-005 | CI | The workflow has run on GitHub for pushes to main (run #4 green except `codeql`). Not yet seen on a pull request; `codeql` is blocked by D-012. | Low | | 00.03 | Open |
| D-006 | API docs | `docs/erp/openapi.yaml` is still written by hand, not generated from the code, so it can drift. A replay snapshot (`tests/contract.test.js`) protects the existing routes, but nothing checks the YAML against the real responses. | Low | Needs a schema-driven API layer; deferred | 01.01 | Open |
| D-007 | Performance | Measured with `npm run erp:gen-data` on 100,000 documents and 249,726 lines in SQLite (2026-10-30, one developer machine): list page p95 0.2 ms, project page p95 0.4 ms, record read p95 0.06 ms, list count p95 87 ms, every query uses an index. The target (list p95 500 ms) is met with a wide margin, but this is SQLite on a laptop: the run must be repeated on PostgreSQL and on production hardware, and the filtered count (the slowest query) watched as tables grow. | Low | Engine and hardware differ from production | 00.03 | Open |
| D-008 | Flags | The page does not hide itself when `ff.prog.p0002` is OFF, because administrators must still reach it to turn flags back on. The flag is evaluated and shown on the page; gating of navigation entries arrives with the shell. | Low | Navigation shell is part 03.x | 03.01 | Open |
| D-009 | Deploy | No staging or production host exists. Deploy, backup, smoke-test and rollback are rehearsed on a directory-based environment on one machine, and production promotion with manual approval is not wired. The server also refuses `NODE_ENV=staging` or `production` until IAM exists (D-001). | High | Hosting target not chosen; depends on D-001 | 00.03, 02.07 | Open |
| D-010 | Pipeline | Branch protection cannot be enforced: GitHub states that rulesets are not enforced on a private repository until it moves to a GitHub Team organisation account (checked on 2026-10-30). No ruleset was created, because an unenforced one would look protective and not be. Until then "no direct push to main, one reviewer" (BR-01) is a team habit, not a control. Making the repository public or upgrading the plan fixes it; the command is in `RELEASE.md`. | High | Free plan, private repository | 00.03 | Open |
| D-011 | Backup | Backups are local files next to the database. `npm run db:rehearse` proved backup and restore with identical checksums on 349,779 rows (41.7 MB): backup 6.1 s, restore 10.8 s (verify 5.5 s, copy 0.02 s, re-check 5.3 s). There is still no schedule, no off-machine copy and no encryption. | Medium | Hosting and backup service not chosen; full DR is part 29.06 | 29.06 | Open |
| D-012 | Security | CodeQL cannot run: GitHub reports "Code scanning is not enabled for this repository" (a repository setting; private repositories may need GitHub Advanced Security). The job is marked non-blocking and is not a required check. `npm audit` and the secret scan do run in CI (first green run 2026-10-30). The secret scanner is a built-in pattern list, not a full scanner. | Medium | Repository setting not enabled | 00.03 | Open |
| D-013 | Release | No release has been cut and no commit carries a `Release-note:` line yet, so user-facing release notes are empty. Coverage threshold is 60 % (target 80 %); client code has no line-coverage gate. | Low | First release not yet decided | 00.03 | Open |
| D-014 | UI | The Architecture page is a document page: it has a table of contents, a filterable and exportable (CSV) error-code table and a live module map, but none of the Report-page extras in the pack (chart, drill-down to records, XLSX/PDF export, schedule by email). Those have no meaning for a static guide. | Low | Reporting framework is part 27.x | 01.01 | Open |
| D-015 | Queue | The queue health check reads the outbox table only. There is no dispatcher or consumer yet, so "stopped queue" means "outbox unreadable" and the backlog and age thresholds (1000 events, 15 minutes) are untested against real delivery. | Medium | Outbox dispatcher is part 01.04 | 01.04 | Open |
| D-016 | Events | Outbox rows written by part 00.02 have a flat payload; rows from 01.01 use the standard event envelope. The dispatcher must read both. | Low | Format changed in 01.01 (ADR-09) | 01.04 | Open |
| D-017 | Storage | The storage health check tests that a local directory is writable. There is no document or file service yet, so remote or object storage is not checked. | Low | Document service is part 04.x | 04.x | Open |
| D-018 | Integrity | The integrity run is synchronous inside the request. Fine today (the schema is small); a large installation needs it as a background job with progress and a notification. | Medium | Job scheduler is part 01.04 | 01.04 | Open |
| D-019 | Idempotency | Stored idempotent responses keep the endpoint's response body in plain text for 24 hours. Retention is fixed and there is no encryption or per-endpoint opt-out. | Low | Data-protection rules arrive with 02.07 | 02.07 | Open |
| D-020 | UI | The Data Health page has the table, tiles, drill-down to history and CSV export, but no chart, no XLSX/PDF export and no scheduled email. | Low | Reporting framework is part 27.x | 27.x | Open |
| D-021 | Back-fill | No real back-fill exists yet (`backfills/` is empty); the framework is proven with test fixtures only. | Low | First schema change that needs one | 01.02 | Open |
