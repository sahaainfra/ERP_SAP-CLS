## Decisions

| Requirement | Existing | Decision |
|---|---|---|
| FR-01 Automated full and continuous backups, file replication, encryption, off-site copy | Backup engine | **New** service: daily FULL and 15-minute SNAPSHOT jobs, each integrity-checked and checksummed, encrypted with AES-256-GCM to the off-site location (`BACKUP_OFFSITE_DIR`, `BACKUP_KEY`) with its hash checked; stored files replicated on each full. Continuous WAL streaming is D-794. |
| FR-02 Retention (14/8/12/7, configurable) | — | **New** retention tiers on each full, parameters `admin.backup.keep_*`, 48 hours of snapshots; expired files are deleted, records kept. |
| FR-03 Restore to isolated environment with validation before production restore | `compareWithManifest` | **New** restore test: decrypt into an isolated folder, then check the off-site checksum, the file checksum, integrity, rows and checksums of every table, and the schema. A production restore needs a backup whose test passed. |
| FR-04 DR runbook, RPO 15 min / RTO 4 h, quarterly drills with reports | — | **New** drills measure the restore time and the data-loss window against parameters `admin.dr.*`; a PDF report; the drill-due check. |
| FR-05 Monitoring and alerts | Notifications | **New** checks (full age, recovery point vs RPO, failure, off-site copy, drill due) every 15 minutes in `ops_backup_alerts`, notifying ITADM. |
| BR-01 Production restore: DIR + ITADM approval and documented incident | Approval engine, `db:restore` | **New** `ops_restore_requests` (incident reference and summary), approved by ITADM then DIR; executed by the operator with `npm run db:restore -- --approved <id>`, which checks the approval, verifies the backup, keeps a safety copy and records the execution. |
