# 25.02 Supplier portal discovery

Part 25.01 is in progress. Parts 15.05 and 22.06 are ready for review and explicitly await acceptance. The development database contains no G1 or G2 sign-off rows. The master UI v3 design and mobile standard and P001–P166 verification report were unavailable in the checkout and attachments. The repository contains the global standards, design assets, and role and approval catalogues.

| Requirement | Decision | Existing service and planned integration |
|---|---|---|
| FR-01 RFQs, documents, quotes and clarifications | Extend | Procurement owns the RFQ, invitation, clarification and quotation records in `proc/rfq.js`. Reuse the shared quotation path into the comparative statement. Supplier documents need a portal-scoped grant. |
| FR-02 PO acknowledgement, schedules and ASN | Extend | `proc/po.js` holds approved orders, schedules and dispatch records. Adopt its supplier-facing acknowledgement and dispatch behavior through an authenticated account. |
| FR-03 GST invoice with PO, GRN and PDF | Extend | `bill/vinv.js` owns vendor invoice capture and matching. Reuse its PO/GRN, GSTIN and duplicate validation. Use the approved attachment service for PDFs. |
| FR-04 Receipt, quality, matching and payment status | Extend | Goods receipts, inspection, invoice matching, AP and payments have separate services. Define minimal supplier projections through each owner. |
| FR-05 VDR and expediting | Extend | `engg/vdr.js` and `proc/xpd.js` own review codes and milestones. Expose the supplier's own records through each with scoped writes. |
| FR-06 Compliance and scorecard | Extend | MDM owns partner compliance documents. `proc/vnd.js` owns vendor evaluations. Reuse both with supplier-only projections and upload grants. |
| BR-01 Deadlines and competitor isolation | Reuse | Procurement owns the RFQ lifecycle and due-date logic. The supplier adapter resolves partner, company, project and site from the existing external session. |
| §5 Database design | Reuse | The existing ERP tables hold the workflow transactions. Add a portal-owned table only if a gap remains after assessing service contracts. |
| §6 Backend and API | Extend | Reuse portal session authorization, transaction handling, version checks, idempotency and outbox contracts. |
| §7 and §7A Portal screens | New | Reuse the authenticated 25.01 shell and existing card, status and attachment components. |
| §8 Roles and access | Extend | Require X-SUP in the existing external session domain. A server-resolved scope carries the source identity to each owning service. |
| §9 Approvals and configuration | Reuse | Transaction decisions stay with the owning workflows. Any new configuration must use existing approval and audit services. |
| §10 Dashboards and exports | Extend | Use scoped live data from service owners and existing export helpers. |
| §11 Module integration | Reuse | Submit through the procurement and invoice services and consume their published events. |
| §12–13 Errors, security and data protection | Reuse | Use the shared error envelope, audit trail and attachment service. |
| §14 Performance | New | Measure list, detail and write paths after the read and write adapters are available. |
| §15–16 Tests and acceptance | New | Verify received supplier quotations through procurement comparison and run supplier browser checks in isolated databases. Complete full acceptance after the prerequisite decisions. |

D-509 remains assigned to vendor selection under 15.08. D-447 is a cross-module and historical integration record. D-659 and D-757 record the invoice hub and portal intake gaps.


The supplier implementation stages files through the shared scanner. RFQ files require explicit publication by procurement. GST invoices use the billing match and Accounts approval chain. VDR items use verified PO links and existing engineering review. Compliance renewals use the partner verification worklist. Programme acceptance remains pending as recorded in the [completion report](../COMPLETION/25.02.md).
