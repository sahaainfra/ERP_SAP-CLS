# Discovery note 04.14

Inspected (searched: comment, mention, timeline, trace, activity, object_type, ui_record_comments, wf_history, doc_links, tsk_tasks, comm_messages, ntf_notifications): no `col_*` table existed. What did exist: the Object Page services of part 03.04 (`modules/ui/objects.js`, `platform/objects`) with a per-record discussion (`ui_record_comments`) and a timeline of audit entries, approvals and comments; the audit log (`core_audit_log`, 02.06) with no project column; the workflow history (`wf_history`, 04.01); document links and versions (`doc_links`, `doc_versions`, 04.10); tasks linked to a record (`tsk_tasks.entity`, 04.08); messages linked to a record (`comm_messages.related_entity`, 04.07); notifications with the category `mentions` (04.06); the parameter engine (02.05); the file service and its entity registry (01.05).

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 threaded comments, @mentions with permission-checked notification, attachments, edit window, reactions | Flat comments in `ui_record_comments`, mention parsing without any access check | New + Reuse | `col_comments`, `col_mentions`, `col_reactions`; attachments are core files of the entity `col_comment`; the old comments stay and are listed read only |
| FR-02 timeline per record and per project merging audit, workflow, comments, document versions, tasks and message threads, with filters | Audit + approvals + comments only, per record | Extend | `collab.js` `timeline.record` and `timeline.project`: read-time merge of existing tables, no copy |
| FR-03 trace links with a panel (upstream, downstream, statuses, amounts) | `related()` hook returning a flat list | New | `col_trace_links`, `trace.graph`, Trace tab |
| FR-04 project activity feed | None | New | `timeline.project`, page Project Activity Feed |
| FR-05 mentions inbox in notifications | Category `mentions` exists, nothing fills it | New + Reuse | `col.mention` and `col.reply` templates (04.06), `mentions.list`, panel on the Notifications page |
| BR-01 a person who cannot view the record cannot be mentioned | None | New | `userCanView` builds the named person's own actor and asks the object type |
| BR-02 trace links made by services; by hand only with a reason | None | New | `trace.add` (service, event `col.trace.requested`), `trace.addManual` (reason of 10 characters or more, database check) |
| Settings (edit window, length, reactions) with audit and approval | Parameter engine | Reuse | three parameters `col.comment.edit_window_minutes`, `col.comment.max_length`, `col.reactions.enabled` |
| Roles: comment needs view; deleting others' comments needs a moderator | Record permissions through the object type | Reuse + New | `col.comment.moderate`, `col.trace.link`, `col.activity.view` |
| Pages: Discussion, Timeline, Trace tabs; Project Activity Feed (Report) | Object Page tabs for the first two | Extend + New | `CollabTabs.jsx`, `ObjectPage.jsx`, `SampleDocsPage.jsx`, `ProjectActivityPage.jsx` |
| API | `/ui/objects/:type/:id/*` | New | `/api/v1/col/*` (the old endpoints keep working) |
| T-01 timeline merges events in order across sources; T-02 trace of a test PO shows PR upstream, GRN downstream | n/a | New | `tests/collab.test.js` |

Reuse rather than rebuild: the object type registry is the only way the engine reaches a record, so a module that registers its type gets all three tabs and the feed without code of its own. Two optional hooks were added to the contract: `summary(db, actor, id)` (one line, status, amount) and `projectRecords(db, companyId, projectId, limit)` (the ids of a project's records, for the feed).
