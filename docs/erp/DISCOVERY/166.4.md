## 2. Findings reproduced on `main`
| # | Proof on `main` | Decision |
|---|---|---|
| P-01 one script of 7.8 MB | `npm run build`: `assets/index-DzxVIJHc.js` **7,696.7 KB, 1,652.5 KB gzip** (level 9; the prompt's 1,686 KB is gzip's default level); the first download is **1,655.7 KB gzip** (`node scripts/bundle_budget.mjs`: FAIL, `docs/erp/perf/166.4/before-bundle-budget.md`) | **Repair** through P-02, the languages and the vendor chunks; budget 350 KB / 250 KB |
| P-02 pages imported statically | 624 `import XPage from './XPage.jsx'` lines in the 24 registries; App.jsx imports 7 more pages (sign-in links, vendor portal, verification, the chat dock) statically | **Extend** the registry contract: `Page: lazyPage(() => import('./XPage.jsx'))` (`platform/shell/lazyPage.js`), drawn by `RoutePage` with a skeleton and a load-failure state; registry metadata stays eager |
| P-02b all three languages in the first download | `shared/i18n/locales/{en,hi,te}.js` are imported by the client translator: Hindi alone is 943 KB of source (177 KB gzip), more than the shell | **Repair**: English in the shell, Hindi and Telugu fetched when the screen is in that language (`loadLanguage`); the screen stays English until the text has arrived |
| P-03 libraries | `pdf.min` and `leaflet` split (kept). `read-excel-file`, `pdf-lib`, `qrcode` and `socket.io-client` are inside the one script; React, TanStack Query and the icons too, so every release changes the one file a phone has to download again | **Extend** `vite.config.js`: `codeSplitting.groups` for React, Query, icons (first download, stable across releases) and xlsx, pdf-lib, qrcode, realtime (with the pages that use them). There is no chart or date library to split |
| P-04 no budget | `scripts/regression.mjs` has no stage on the size of the build | **New** `scripts/bundle_budget.mjs` (report in `reports/bundle-budget.{json,md}`), stage `bundle-budget` of `erp:regression`, `npm run erp:bundle-budget` |
| P-05 nothing is compressed (found while reproducing) | `curl -H 'accept-encoding: br, gzip' /assets/index-*.js`: no `Content-Encoding` (on `main` the one script is 7.7 MB on the wire), and `Cache-Control: public, max-age=0` on the hashed files, so the browser asks again for each of them | **New** pre-compressed `.br`/`.gz` copies written by the build and `platform/http/staticAssets.js` (a year's `immutable` cache for `/assets/`). No new dependency (Node's zlib) |
| P-06 the precache downloads everything | the worker's install list is every file of the build (after P-02: 721 scripts, 1.8 MB gzip) | **Repair**: the shell and the pages a site person needs offline (home, field home, scan, field forms, sync status, conflicts, phone approvals, DPR entry); any other page is kept when first opened |
| P-07 the English text is downloaded twice (found with Lighthouse) | `GET /api/v1/ui/translations/en/all` returns the whole effective catalogue (489 KB of JSON, not compressed) on every start, although the same text is in the bundle; the client then drops what equals the bundle | **Repair**: `?only=overrides` returns only the company's own wording (empty when it changed nothing); **New** `platform/http/compressJson.js`: JSON answers above 1.4 KB compressed (the menu: 181 KB → about 30 KB) |
| P-08 the first screen does work it does not show (found with Lighthouse) | on a phone the closed menu drawer draws every entry of the person's menu; the chat dock and its real-time client start with the first screen; the bottom-bar prefetch competed with the page's own data | **Repair** with the flag: the phone drawer draws its entries when opened; the chat dock waits until the browser is idle; the prefetch waits 4 s and idle; the opened page's code is fetched together with the sign-in check |
