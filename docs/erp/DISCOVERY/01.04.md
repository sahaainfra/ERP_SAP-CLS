# Discovery note 01.04

Inspected: after part 01.03 the repository had `core_outbox` (event_type, aggregate_id, payload, published_at) and a `publishEvent` helper that every module already calls inside its transaction, `core_audit_log`, idempotency, integrity checks, the approval stand-in (`platform/approvals`) and the admin shell. Search terms (background, core_event_types, core_inbox, core_jobs, core_outbox, core_schedules, domain, event, outbox, scheduler, transactional) found only the outbox and `publishEvent` (written in 00.02 with a comment that dispatch belongs to this part) and the health check that counts unpublished outbox rows. There was no relay, consumer, inbox, retry, dead letter, replay, job or scheduler.

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 transactional outbox written in the business transaction; relay worker | Outbox table and `publishEvent` (no relay) | Extend | `publishEvent` unchanged in contract; `bus.relayOnce`, `startWorkers`; `core_outbox` itself not altered (ADR-29). Socket.IO relay not built (D-026) |
| FR-02 standard event envelope | Partial (no type, version semantics or correlationId) | Extend | `platform/events/publish.js`: eventId, type, version, occurredAt, companyId, projectId, siteId, entity, entityId, actorId, correlationId, data; the old entity version is kept as `entityVersion` |
| FR-03 event catalogue with schema versions and validation on publish | None | New | `platform/events/registry.js`, `core_event_types`, `modules/core/operations.js` (24 core event types) |
| FR-04 consumer framework: inbox de-duplication, back-off retries, dead letters, manual re-drive | None | New | `core_inbox`, `platform/events/bus.js` (`subscribe`, `deliverOnce`, `redrive`, `discard`) |
| FR-05 replay by type and date range, side effects suppressed | None | New | `bus.replay` (`ctx.replay`), job `core.event_replay`, `POST /events/replay` |
| FR-06 background jobs with progress, cancellation, retries; cron schedules with a lock so one instance runs; history | None (the back-fill runner of 01.02 is a command-line tool, not a queue) | New | `core_jobs`, `core_schedules`, `platform/jobs`, `src/shared/cron.js` |
| FR-07 admin console: throughput, lag, failures, DLQ re-drive, job list | Data Health page only | New | Four pages under `/admin/operations/...`, API `events`, `jobs`, `schedules` |
| BR-01 an event exists only if its transaction commits | Holds by construction (same connection) | Reuse, prove | T-01 |
| BR-02 idempotent consumers | None | New | unique (consumer, eventId); handler and mark in one transaction |
| BR-03 replay sends no notifications | None | New | `ctx.replay` flag, test with a notifying handler |
| Maker-checker for configuration changes (AC-06) | Approval stand-in (D-022) | Extend | schedule changes use `platform/approvals` (ITADM asks, SYSADM approves); migration 13 removes the request-type CHECK (ADR-31) |

Departures from the pack: dispatch state is in a new `core_inbox` instead of extra columns on `core_outbox` (status, attempts), so the pre-existing table is not altered; no message broker or Socket.IO (D-026). Tables added: `core_event_types`, `core_inbox`, `core_jobs`, `core_schedules` and `core_projection_event_counts` (the read model used to prove replay). Pages: Events & Jobs Monitor, Dead-Letter Queue, Background Jobs, Scheduled Jobs. Permissions: `core.events.view` (ITADM, SYSADM), `core.events.redrive`, `core.events.replay`, `core.jobs.view` (ITADM, SYSADM), `core.jobs.manage`, `core.schedule.view` (ITADM, SYSADM), `core.schedule.manage` (ITADM only).
