## Findings reproduced on `main`

| # | Finding | Evidence on `main` | Decision |
|---|---|---|---|
| F-01 | The module dashboards are not overview pages: each has its own filter form, a row of tiles and tables; no card has a title + subtitle + big KPI + chart/list; no "View all ›"; nothing can be arranged or kept per person | `before-{hr-overview,qs-dashboard,control-tower,qa-dashboard,hse-dashboard,proc-dashboard,stores-dashboard,materials-dashboard,plant-dashboard,plant-utilisation,budget-ledger}-*.png` | **Extend**: each dashboard gets a dashboard code on the 03.07 framework whose widgets call the dashboard's existing service (no new metric) |
| F-02 | Home (Launchpad) has tiles of pages and counts, no insight for the person's role | `before-home-*.png` (PM) | **Extend**: Home insight cards by role (a dashboard `home-insights` with a default per role) |
| F-03 | The card catalogue misses a Top-N card (name, value, bar), a to-do card with Approve / Return, a scatter chart; the KPI card has no subtitle (unit · period) and no deviation from target | `WidgetBody.jsx`, `ui_widgets.type` CHECK | **Extend** `WidgetBody`/`Chart`; the `type` CHECK of `ui_widgets` gains `topn`, `todo`, `scatter` (table rebuild migration with up and down, `DB_CHANGES.md`) |
| F-04 | Sizes are columns 1–12 and rows 1–4 by buttons; there is no S / M / L / XL | `Dashboard.jsx` edit controls | **Extend**: S = 3, M = 6, L = 8, XL = 12 columns in "Customise" (the 12-column grid stays) |
| F-05 | A chart has no "Show as table" outside low-bandwidth mode; the legend is beside the chart on a phone | `Chart.jsx` | **Extend**: a "Show as table" switch on every chart; legend below on a phone; at least 220 px tall on a phone |
| F-06 | Drill-down: dashboards link to lists without the dashboard's filters | the pages' links (`Link to="/inv/balances"`) | **Extend**: every card's "View all ›" carries the project, site and period (`withDashFilters`) |
