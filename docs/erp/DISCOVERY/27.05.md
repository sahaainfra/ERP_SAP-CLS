## Decisions

| Requirement | Existing | Decision |
|---|---|---|
| FR-01 Sections per role, fixed cut-off | Role templates, scope filters | **New** `mr_configs` (per role or user; sections, cut-off, delivery time, channels). Each report is built as its recipient, so every figure honours their permissions and scope. Source reads use a cut-off where the source keeps a time (DPR submission, workflow task creation). |
| FR-02 Rule-based executive summary | — | **New**: sentences generated by rules from the section figures, labelled rule-based. The AI summary waits for 28.02 (D-773). |
| FR-03 Scheduled delivery, PDF, interactive version, archive | Notification engine, export writer, job scheduler | **New** job every 15 minutes: one report per recipient and date, at the configured time, through the notification engine (in-app; e-mail and WhatsApp by recipient preference and channel). PDF, XLSX and CSV are drawn from the snapshot on download, and the interactive page reads the same snapshot. The PDF is not stored as a file and is not attached to the e-mail (D-774). |
| FR-04 Exceptions | — | **New**: DPRs missing, overdue approvals, stock-outs, collections due today and lost-time incidents, worst first. |
| BR-01 Reproducible figures | — | **New**: a canonical JSON snapshot with its SHA-256 is stored in `mr_reports`. Reopening, verifying and exporting use the snapshot, so later data never changes the report of a date. |
| §9 Configuration approvals | Change-request engine | **Reuse**: DIR or CFO approves, never the requester; old and new values are audited. |
| §8 Roles | Role templates | **New** permissions: `bi.morning_report.view` for DIR, PD, PM, CFO, PROCMGR and COMMGR; `bi.morning_report.configure` for DIR and CFO. Reports are personal: only the recipient opens them. |
