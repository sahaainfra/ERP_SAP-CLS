# Discovery note 03.03

Inspected (searched: component, data, list, report, table, ui_saved_views, saved view, variant, column chooser, export, xlsx, pdf, bulk, totals): there is no list component. Every register builds its own table from `<table>`, a search box, selects for filters, the `Pager` of `core/pages/ui.jsx` (previous/next, no page sizes on most pages) and `downloadCsv` (fetches every page in the browser and writes CSV there, then logs the export through `logExport`). The users register (02.03) is the most complete: per-browser saved views and column choice in `localStorage`, a bulk bar (invite, suspend) with a result summary, CSV export, and a server export guard (`platform/security/export.js`, 02.07: `*.export` permission, `core.export.max_rows`, approval for large personal-data exports, audit and security event). `ui_user_preferences.table_settings_json` (03.01) stores table settings but nothing reads them (D-117). Field masks exist (`authz.mask`, `fieldRegistry`, 02.04) and are applied by the services that know a field is sensitive. The list query contract is `parseListQuery` (page, pageSize up to 200, q, sort `-a,b`, `filter[x]=value`, from/to); there are no operators, no totals and no server export of a list. No XLSX or PDF library is installed. Jobs (01.04) and file storage (01.05) exist; in-app notifications do not (04.07). Parts 03.01 and 03.02 are complete in the working tree, awaiting commit.
