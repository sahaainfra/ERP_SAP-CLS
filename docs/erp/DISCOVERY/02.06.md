# Discovery note 02.06

Inspected: `core_audit_log` (part 00.02) has been written by every part through `writeAudit` (121 call sites) with entity, record, action, old and new values, reason, actor and correlation ID; nothing stopped an UPDATE or DELETE, no entry was linked to the one before, nothing recorded where a request came from, and sign-in history lived only in `iam_login_events` (02.01). There was no security event log, no audit viewer, no record history, no export logging and no retention (searched: audit, core_audit_log, core_security_events, trail, hash, tamper, export, print). The event bus and outbox exist (01.04) and every part publishes domain events; the schema baseline forbids changing an existing table.

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 audit service API `record(entity, id, action, before, after, reason, context)` | `writeAudit` with old and new values | Extend | `platform/audit` (`writeAudit` unchanged for callers, new `record`); every existing call is chained without being edited |
| FR-02 field-level diff ignoring technical columns; masked sensitive fields | Raw old and new JSON | New | `diff.js`; masked at write time in the stored diff and at read time for older raw columns (ADR-99) |
| FR-03 hash chaining, periodic verification, tamper alert | None | New | `core_audit_chain` beside the log (ADR-95), `chain.js`, nightly job `core.audit_verify`, critical security event and domain event |
| FR-04 security event log | Login history only | New | `core_security_events`; fed by `publishEvent` (ADR-98), sign-in failures, refused requests and exports |
| FR-05 export and print logging | None | New | `POST /core/audit/export-log`; the browser reports CSV exports and prints; `report` entries in the audit trail |
| FR-06 audit viewer and a record History component | Per-page history on users and organisation | New | Audit Explorer, `RecordHistory`, `GET /core/audit` and `/audit/history` |
| FR-07 retention and archival, never deletion within retention | None | New | monthly sealing and export, parameter `core.audit.retention_months`; no delete path (D-101) |
| FR-08 import legacy logs into the viewer, read-only | `iam_login_events`; the old audit rows | New | old audit rows chained in order at start-up; old sign-in failures copied once into the security log |
| BR-01 no update or delete by any application role, enforced in the database | None | New | triggers on all four tables; honest limit in D-100 |
| BR-02 chain verification failure raises a critical alert | None | New | critical security event once per new break, `core.audit.tamper_detected` |
| Tables `core_audit_log` (partitioned) and `core_security_events` | Log exists | Extend / New | the log is not altered; chain, events, verifications and segments are new |
| Roles: AUD full read; SYSADM and ITADM security events; record viewers History | Permission engine (02.04) | New | `core.audit.view`, `core.audit.verify`, `core.security.view`; History by the right to view that kind of record |
| T-01 diff with masking; T-02 UPDATE on an audit table fails; T-03 tampering detected | None | New | `tests/audit-api.test.js` |

Departures from the pack: partitioned tables are not available in SQLite, so months are sealed instead (D-101); append-only is enforced by triggers rather than database privileges (D-100); notification of a tamper alert waits for 04.06 (D-105).
