# Discovery 11.01: Drawing register, revisions, transmittals and distribution

Inspected: the document management service (04.10: documents, versions, the register, distribution with acknowledgement), the file service and its entity registry (01.05), the workflow engine with resolvers and evidence providers (04.01), notifications (04.06), the project master, WBS, locations and BOQ (10.01 to 10.04), the navigation registry, the list and export engines, the integrity registry, the roles DOC, DESIGN, CM, SE, PM and X-CON in the role templates, and the module registry. No `engg` module existed; M11 starts here.

| Requirement | Decision | Notes |
|---|---|---|
| FR-01 drawing register with number, title, discipline, package, WBS/location, scale, size, originator, current revision and status code, issue purpose | New | `engg_drawings`; the optional `document_id` points at a 04.10 document (the file and its versions stay in the file service, nothing is copied). |
| FR-02 revision workflow (receive/upload, check, approve IFC, issue); change note, revision-cloud summary; side-by-side compare | New + Reuse | `engg_drawing_revisions`; workflow `ENGG_DRAWING_IFC` (document control, design coordinator, project manager) for IFC only; the other status codes (IFR, IFA, as-built) issue at once on submit. The compare viewer shows the data differences and both files. |
| FR-03 transmittals outgoing and incoming with purpose, recipients, due date, acknowledgement and response codes A to D | New | `engg_transmittals`, `engg_transmittal_items`; outgoing "for approval" goes through `ENGG_TRANSMITTAL` (document control, design coordinator); responses are recorded per drawing and close the transmittal when all are in. |
| FR-04 site distribution: controlled copies with acknowledgement; superseded revisions marked and restricted; mobile shows current IFC only | New | `engg_copies`; the file entity `engg_drawing_revision` closes the file of a draft, waiting or superseded revision to anyone without the right to edit or approve; the site page lists the current IFC only and keeps the last list on the phone. |
| FR-05 links to BOQ, activity and location (read by 14.01) | New | `engg_drawing_links` (WBS, location, BOQ item validated against the project; activity as a programme reference until 13.x); `drawingsForTarget` and `drawingUseCheck` are exported for later parts. |
| FR-06 drawing schedule, planned against actual receipt, overdue report | New | `/engg/schedule` and the dashboard. |
| BR-01 only IFC is usable for execution | New | `usable` on the drawing, `/engg/drawings/use-check` and `drawingUseCheck` return OK only for the issued IFC revision; every other case says why (superseded, not IFC, unknown). Work authorisation (14.01) will call it; this part gives the answer and does not block anything yet. |
| BR-02 a new IFC supersedes the previous and notifies all holders of controlled copies | New | a transaction in `issue()`: older issued revisions of equal or lower rank become SUPERSEDED, their copies are superseded, replacement copies are made for each holder, and the template `engg.drawing.superseded` and the event of the same name go out. |
| Events | New | `engg.drawing.issued`, `engg.drawing.superseded`, `engg.transmittal.issued`, `engg.transmittal.response`. |
| Permissions | New | `engg.drawing.*` and `engg.transmittal.*` with the standard actions plus `distribute` and `respond`. |
| Shared services | Reuse | workflow, files, notifications, lists and exports, audit, integrity registry, i18n, feature flags, navigation. |
| RFIs on the drawing page | Deferred | 11.02 supplies them; the tab says so. |
