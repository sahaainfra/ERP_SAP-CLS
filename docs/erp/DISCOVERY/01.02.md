# Discovery note 01.02

Inspected: after part 01.01 the database layer was a migration runner (`platform/db/index.js`: timestamped up/down files, one transaction each, a ledger table), a migration up/down check, schema-diff against a locked baseline, a `VACUUM INTO` restore point inside the deploy tool, and an optimistic-update and soft-delete helper. Search terms (core_idempotency_keys, core_integrity_runs, data, database, foundation, framework, integrity, migration) matched only those. There was no idempotency store, no integrity suite, no schema lint, no company-scope helper, no back-fill framework, no backup manifest, no performance data generator, and `docs/erp/DB_CHANGES.md` was the only schema record. The pack's `npm run erp:db-check` did not exist. Prerequisite 01.01 is "Ready for review" (not yet Accepted) and was reused as is.

|---|---|---|---|
