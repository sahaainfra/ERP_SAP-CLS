# Discovery note 02.03

Inspected: after part 02.02 there was a thin user store (`iam_users`, D-059) that held just enough to sign a person in, created by a script or a service call. There was no lifecycle, invitation, employee link, department, profile, user page or import (searched: employee, iam_invitations, iam_users, linking, management, onboarding, state, user). Sign-in, sessions, MFA and the password policy (02.01) and the organisation master (02.02) exist and are called, not copied. The employee master (07.01) and the role engine (02.04) do not exist, so adapters are used and recorded as defects.

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 user record: name, username, email, mobile, language, employee link, type, status | `iam_users` with name, username, email, mobile, roles, ACTIVE/DISABLED | Extend | `iam_user_profiles` (lifecycle, type, language, employee code, department, home project); employee link is a code until 07.01 (D-076) |
| FR-02 invite by email or mobile, set password and MFA, expiry, resend | None; MFA set-up at sign-in exists | New | `iam_invitations`, `usermgmt/service.js`, `/accept-invite`; MFA is asked at first sign-in for roles that need it (D-082) |
| FR-03 restricted onboarding state, deny by default | Permissions empty for no role, but some routes answered | New | `platform/http/onboarding.js`, Welcome page; walk of every documented route in `tests/users-api.test.js` |
| FR-04 bulk import with validation | None | New | CSV adapter `usermgmt/import.js`, `UserImport.jsx` (D-078) |
| FR-05 deactivation: immediate session revocation, reassignment wizard, history kept | Session revocation helper exists | Extend | deactivation check and wizard, `approvals.reassignRequester`, `orgService.reassignHoldings`, `userBlockers` registry |
| FR-06 profile: photo, signature, language, notification preferences, theme | Own sessions and MFA page | New | `ProfilePage.jsx`, `PATCH /iam/me`, files through the document service (entity `iam_user_profile`) |
| FR-07 duplicate detection on email, mobile, employee link | Unique indexes without a message | Extend | `duplicates()`, live warning in the invite form, 409 `DUPLICATE_USER` |
| BR-01 one active account per person; email and mobile unique | Unique indexes on email, mobile, username | Extend | normalised mobile, employee code unique, deactivated person keeps the account (ADR-77) |
| BR-02 deactivation with pending approvals forces reassignment | None | New | blockers list, successor required, steps nobody else can decide block |
| Endpoints: CRUD users, invite, suspend, deactivate, reactivate, GET and PATCH me | `GET /iam/me` | New / Extend | `usermgmt/routes.js`; `profileExtras` added to `GET /me` |
| Approval: user with a privileged role request | Interim engine | Extend | request type `user_role_assignment` (D-077) |
| Pages: Users list, User object, Invite and Import, My Profile | None | New | `UsersPage.jsx`, `UserPage.jsx`, `UserImport.jsx`, `ProfilePage.jsx`, `AcceptInvitePage.jsx`, `WelcomePage.jsx` |
| Roles: SYSADM and HRMGR manage, ITADM view and suspend, everyone own profile | Role map constant | Extend | `iam.user.view`, `iam.user.manage`, `iam.user.suspend` |
| Shared services: numbering (01.03), calculation (01.06), event bus (01.04) | Exist | Event bus used; numbering and calculation not applicable | users are identified by username; no document number or calculation arises |
| T-01 no role gives 403 on every module API | None | New | `tests/users-api.test.js` |
| T-02 deactivation revokes sessions within 60 seconds | Session check per request | New proof | immediate: the next request fails (`tests/users-api.test.js`) |
| T-03 bulk import rejects duplicates with row errors | None | New | `tests/users-api.test.js`, E2E |
