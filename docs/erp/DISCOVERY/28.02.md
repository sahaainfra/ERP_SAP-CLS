## Decisions

| Requirement | Existing | Decision |
|---|---|---|
| FR-01 Assistant panel in the shell, aware of the page | Shell extras | **New** dock (button "Ask AI" and a side panel; a bottom sheet on phones) in the shell when `ff.ai.p2802` is on; it sends the `projectId` and the route of the page. **New** page `/ai/assistant` (My Work). |
| FR-02 Plain words → governed queries, query shown, records cited | Metrics, datasets, explainer, inventory | **New** `parseQuestion` matches a question to METRIC, VARIANCE (why), STOCK or PROJECT_STATUS; the query runs through the owner's service **as the person** inside the gateway context. The answer shows the query that ran and links the records. An unmatched question or one with no data gives an "unsure" answer with no model call (BR-01). |
| FR-03 Drafts created as drafts in the target module | Engineering services | **New** `ai_drafts` keeps the proposal (PROPOSED). Only when the person reviews and saves it does the module's own service create a DRAFT record (RFI, outgoing letter) with the module's permissions; other kinds stay as text (D-782). |
| FR-04 Role copilots | 27.08, 27.09, purchase orders, control tower | **New** features `ai.copilot_pm` (schedule and look-ahead), `ai.copilot_qs` (leakage, margin), `ai.copilot_procurement` (a vendor's orders) and `ai.copilot_finance` (cost and margin), read-only, each enabled per role through the 28.01 approval. |
| FR-05 Feedback and evaluation logs | `ai_logs` | **New** `ai_feedback` (one vote per answer and person, on their own answers only) and a summary by feature for `ai.usage.view`. The evaluation cases of each feature run through the 28.01 harness before approval. |
| BR-01 Only retrieved data; says when unsure; no action without confirmation | Gateway system prompt and tools | **Reuse**; the new features declare READ or DRAFT tools only; saving a draft is an explicit action of the person. |
| [Config] Copilot prompts per role | 28.01 feature versions | **Reuse**: prompts are versioned in code and enabled per role through the SYSADM → DIR approval (audited, maker-checker). |
| D-779 (27.08 narrative) | `ai.variance_narrative` (28.01) | **Extend** the Why? page with "Explain in words (AI)". |
| Roles | 28.01 enablement | No new permission keys: who may use a feature is its approved enablement; the data is decided by each owner. |
