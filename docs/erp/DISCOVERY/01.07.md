# Discovery note 01.07

Inspected: after part 01.06 the application had a request logger (one JSON line per request with a correlation ID and the raw user name), a correlation ID middleware, a health endpoint (`/api/health`, `/api/health/ready`), the event bus and job runner of 01.04 (with their own metrics page), and a client API client that sends a correlation ID with each call. There was no redaction, no metrics beyond event and job counts, no tracing, no browser error reporting, no objectives or alerts, and no load test. The logger wrote the user name and the bus and runner wrote nothing under the request's correlation ID.

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 structured JSON logs with level, time, correlation ID, pseudonymised user, module, route, duration; PII redaction | JSON request line with raw user, no redaction | Extend | `platform/observability/redact.js`, `context.js`; `platform/http/logger.js` redacts every entry; request line carries route pattern, module, duration, `u_` pseudonym |
| FR-02 metrics: request rate, latency, errors by route; DB pool; slow queries; queue depth; job durations; socket connections; cache hit rate | Event and job counts only | New | `platform/observability/metrics.js`, `dbstats.js`; `GET /metrics`; sockets and pool not measurable (D-048) |
| FR-03 distributed tracing | None | New (own tracer) | `platform/observability/tracing.js`, W3C `traceparent`, OTLP/JSON export; SDK not installed (D-046) |
| FR-04 frontend error and performance reporting with correlation ID | API client already sends the ID | New | `client/platform/observability/reporter.js`, `onFailure` hook in `createApiClient`, `POST /ops/client-events`, `core_client_events` |
| FR-05 objectives for login, attendance punch, DPR submit, PO approval, payment run, with error budgets | None | New | `core_slo_definitions`, `evaluateSlo`; eight journeys, four of which have no route yet (D-049) |

Departures from the pack: the OpenTelemetry SDK is not installed, so the application has its own tracer (ADR-51, D-046). Email and WhatsApp cannot be sent (no notification engine, D-047), so alerts are recorded and shown with "not configured". Login, attendance, DPR, purchase order and payment have no routes yet; their objectives exist and show "no data" (D-049). Two journeys that do exist were added: approval decision and bill calculation, plus file upload.

Finding recorded by the baseline: the Events log took 1.4 s at 100,000 events (standard 500 ms). It now browses the latest 20,000 and measures 293 ms (D-045, ADR-54).
