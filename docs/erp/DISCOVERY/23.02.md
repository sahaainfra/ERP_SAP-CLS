## Requirement by requirement

| Requirement | Decision | What |
|---|---|---|
| FR-01 rule matrix: event × conditions → accounts, dimensions, amounts, narration; versioned, dated | **New** | `fin_posting_rules`: conditions on the event's fields (eq, ne, in, gt …), lines (account code, side, amount = an expression of the calculation engine **Reuse 01.06**, dimension mapping, narration template), version and date; template rules (no company) a company replaces by its own version of the same code |
| FR-02 consume the outbox, one journal per event, link | **Reuse** (bus, 23.01 `postEngine`) + **New** | consumer `fin.posting`; `fin_posting_log` unique per event; the journal unique per source document; `fin.document.posted` back to the source |
| FR-03 replay with dry run | **New** | `fin_replay_runs`: the outbox events of the types and dates not yet in the log; the dry run (count, amount, failures, a hash); the commit on approval (ACCMGR → CFO) |
| FR-04 failed postings queue | **New** | the log's FAILED rows with the reason (NO_RULE, SUPPLY_UNKNOWN, MISSING_ACCOUNT, DIMENSION, PERIOD_CLOSED …), re-post (one, all), resolve (by a journal) or ignore (with a reason); notification to the holders of `fin.posting.repost` |
| FR-05 sub-ledger to GL reconciliation | **New** | AP, AR, inventory, GRNI, retention, advances against their control accounts |
| FR-06 default rule set | **New** (reference seed) | GRN, return to vendor, issue, vendor invoice (PO / service / hire, GST split by the state of supply), subcontractor bill, tax invoice and its cancellation; account **240002 Goods received not invoiced** added |
| BR-01 one event, at most one journal; rule changes from their date | **New** | unique keys; the rule in force on the event's date; a back-dated change needs `backdate` and history changes only through a replay |
| §9 approvals | **Reuse** (workflow engine) | `FIN_POSTING_RULE` (CFO), `FIN_REPLAY` (ACCMGR, then CFO) |
