# Discovery note 03.02

Inspected (searched: components, data, entry, form, framework, ui_drafts, ui_form_metadata, draft, lookup, grid, autosave, duplicate): there is no form framework. Pages build forms by hand from `Field`, `FieldError`, `FormDialog` and `errorInfo` in `src/client/modules/core/pages/ui.jsx` (labels, a server-error map by field name, a modal with a reason box); inputs are native `<input>`/`<select>`; money and dates are shown with `formatINR` and `formatDate` from `src/shared` (exact decimals, Indian grouping, DD-MMM-YYYY) but no input parses grouped numbers. There are no drafts (server or browser), no generic lookup contract (one ad-hoc `GET /iam/org/lookups/users`, 50 rows, no paging), no line grid, no duplicate check, no "create from", no unsaved-changes guard and no form metadata. Masters that exist and can be looked up: projects, sites, cost centres, departments and users (02.02, data-scoped by 02.04), units of measure (`core_uoms`, 01.06), holiday calendars (`GET /core/holidays/check` one date at a time), number series (01.03), the calculation engine with `boq.line_amount` (01.06) and the file service with record types (01.05). Items, vendors, stores and item categories (M06) do not exist yet. The shell keeps the working project and site in the browser (`workContext()`, event `erp:context`) and navigates with `pushState` in `App.jsx` and `navigateTo` in `ui.jsx`. Part 03.01 is complete and awaiting commit (working tree).
