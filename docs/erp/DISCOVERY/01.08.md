# Discovery note 01.08

Inspected: after part 01.07 the repository had the event bus, jobs and scheduler (01.04), the interim approval engine (D-022), the audit trail, redaction and correlation (01.07), the files module with its own secret (`FILE_URL_SECRET`) and a public route mounted before sign-in (01.05). There was no connector registry, no credential store, no outbound call wrapper and no webhook receiver; no module called an outside service yet.

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 connector registry: type, provider, environment, status | None | New | `core_connectors`, `modules/core/connectors`, Connectors page |
| FR-02 credentials vault: encrypted, rotation dates, masked, only the integration service reads | None | New | `core_connector_secrets`, `platform/integrations/vault.js`, `VAULT_KEY`; values staged and promoted on approval |
| FR-03 provider abstraction | None | New | `platform/integrations/providers.js` (registry, type interfaces, sandbox and HTTP providers) |
| FR-04 outbound wrapper: timeout, retry with back-off, circuit breaker, rate limit, idempotency key | None | New | `platform/integrations/hub.js`, `breaker.js` |
| FR-05 request/response log with redaction, duration, status, correlation ID, retention | Redaction and correlation from 01.07 | Extend | `core_integration_logs`, `logText`, purge job, Integration Log page |
| FR-06 inbound webhooks with signature and replay protection | Public router (01.05) | New | `POST /webhooks/:connector`, `webhooks.js`, `core_webhook_receipts`, raw-body capture in the pipeline |
| FR-07 health checks and test connection | Job scheduler (01.04) | New | `hub.testConnection`, job `core.connector_health` every 15 minutes, Test connection button |
| BR-01 secrets write-only, never returned by an API | None | New | no read function except `secrets.read`; test T-03 scans every table and response |
| BR-02 configuration changes maker-checker and audited | Approval engine (D-022) | Extend | request type `connector_change`; chain SYSADM, plus CFO for bank and GST |
| Roles: ITADM configure, SYSADM view, CFO approve banking | Permission adapter | Extend | `core.connectors.view`, `core.connectors.configure` |
| Events | Event catalogue | Extend | `core.connector.changed`, `core.connector.health_changed`, `core.webhook.received` |

Departures from the pack: the dedicated providers (SMS and WhatsApp gateway, GST, bank, biometric, AI) belong to the parts that use them; this part ships the framework, a sandbox and an HTTP email provider, and a generic HTTP JSON provider for the other types (D-052). Disabling a connector is immediate and audited, not an approved request, because an outage needs a kill switch (ADR-59). Circuit state and rate counters are per process (D-053). Connector codes are unique across the system, because the public webhook URL names the connector before any company is known (ADR-60). The pack's tables do not name an approval table; approvals use the existing change-request engine.
