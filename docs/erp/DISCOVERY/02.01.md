# Discovery note 02.01

Inspected: after part 01.08 there was no sign-in at all. `AUTH_MODE=dev-headers` trusted `X-Erp-*` request headers (D-001), the role-to-permission map was a constant, `config.js` refused `AUTH_MODE=iam`, and the browser had a development identity bar. There was no user table, no password hash, no session and no MFA, so there were also no existing users or legacy password hashes in this repository; the legacy-hash path is built and tested against the formats named in the test, and the first users are created by script. The user master (02.03) and the organisation tables (02.02) do not exist; the vault and the integration hub (01.08) do.

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 login by username/email/mobile and password; Argon2id; legacy hashes upgraded on next login | None | New | `platform/identity/password.js`, `modules/iam/auth.js`; verifiers for pbkdf2_sha256, scrypt, salted sha256 |
| FR-02 MFA: TOTP, SMS/WhatsApp OTP, mandatory for privileged roles, remember device 30 days | None | New | `platform/identity/totp.js`, `modules/iam/mfa.js`; text/WhatsApp through the 01.08 connectors (04.07 not built) |
| FR-03 password policy: length 10, breached check, expiry, history of 5 | None | New | `platform/identity/policy.js`; local list plus optional k-anonymity check |
| FR-04 lockout with progressive delay; CAPTCHA after a threshold | None | New | `iam_login_throttle`; signed arithmetic CAPTCHA (D-063) |
| FR-05 forgot password with expiring code | None | New | email on file through the 01.08 email connector; mobile delivery is D-066 |
| FR-06 sessions: cookie or JWT with refresh rotation; idle and absolute timeout; concurrency limit | None | New | access token plus rotating refresh cookie, session row as authority |
| FR-07 device and session management; admins force sign-out | None | New | My Sessions & Devices, Login History tabs |
| FR-08 login history and suspicious-login alerts | None | New | `iam_login_events`, `iam.login.suspicious`, email to the person; country needs a proxy header (D-064) |
| FR-09 OIDC/SAML readiness | None | New, configuration only | SSO block of the policy (D-061) |
| FR-10 field mode PIN/biometric | None | New, PIN only | device PIN, `/auth/pin-unlock` (D-062) |
| BR-01 errors never reveal whether the username exists | None | New | one message, status and time for every failure; decoy hash |
| BR-02 privileged roles cannot log in without MFA | None | New | policy role list; enrolment is part of the sign-in |
| BR-03 legacy hashes upgraded transparently | None | New | at the first successful sign-in, audited |
| Config page and maker-checker (AC-06) | Interim approval engine (D-022) | Extend | request type `auth_policy_change` |
| Roles: all users own sessions/password; SYSADM/ITADM policy, forced sign-out, history | Permission adapter | Extend | `iam.security.view`, `iam.security.manage` |

Departures from the pack: the users table is a thin stand-in (D-059); SSO is configuration only (D-061); the second step by text or WhatsApp goes through the integration hub because the communication gateway (04.07) does not exist (D-066); there are no legacy users to migrate, so T-04 is proved with imported hashes in the old formats. The sign-in routes are not behind the feature flag, because the flag cannot decide how a person who is not yet known signs in (ADR-66).
