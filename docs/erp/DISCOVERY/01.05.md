# Discovery note 01.05

Inspected: after part 01.04 the repository had no file handling of any kind. Search terms (attachment, core_files, file, secure, service, storage) found only the `storagePath` setting used by the readiness check (a writable-folder test, D-017), the CSV export helper on the client, and the shared numbering and event services this part must use. There was no upload endpoint, body parser for files, table, virus scan, thumbnail, signed link or upload component.

| Requirement | Existing | Decision | Where |
|---|---|---|---|
| FR-01 storage adapter, bucket or folder per company, local disk in development | Writable-folder health check only | New (local adapter; S3 not built, D-033) | `platform/files/storage.js`, keys `c<company>/<year>/<month>/<uuid>` under `<storage>/files` |
| FR-02 multipart and resumable uploads, size limit per type, configurable | None | New | `modules/core/files` (`POST /files`, `/files/uploads...`), `core_file_uploads`, `src/client/platform/files/upload.js` |
| FR-03 extension and magic-number allow-list, virus scan, quarantine | None | New | `platform/files/types.js`, `platform/files/scan.js` (built-in test scanner plus clamd), job `core.file_scan`, `quarantine/` (D-031) |
| FR-04 metadata: name, MIME, size, SHA-256, uploader, linked record, photo time and GPS, EXIF strip on request | None | New | `core_files`, `platform/files/exif.js` |
| FR-05 thumbnails and previews, video streaming | None | New (images and byte ranges; PDF thumbnails not built, D-034) | `sharp` in the scan job, `GET /files/:id/content` with Range |
| FR-06 signed short-lived download URLs, access checked against the linked record | None | New | `platform/files/signing.js`, `GET /files/:id/url`, `platform/files/entities.js` |
| FR-07 duplicate detection by checksum within the entity | None | New | `DUPLICATE_FILE` (409) |
| FR-08 upload component: drag-drop, camera on mobile, progress, retry, preview | None | New | `FileUploader`, `AttachmentList` |
| BR-01 not downloadable until CLEAN | None | New | `FILE_NOT_AVAILABLE` (409) |
| BR-02 download needs view permission on the linked record | None | New | file entity registry; `sample_document` registered |
| BR-03 soft delete; files of approved records only superseded | Soft-delete columns on every table | Extend | `remove`, version chain (`supersedes_id`, `version_no`) |
| Settings page: types, limits, retention mapping, scan overview, maker-checker | Approval stand-in (D-022) | Extend | `core_file_settings`, File Storage Settings page, request type `file_settings_change` |
| Shared services: numbering (01.03), event bus (01.04) | Both exist | Reuse | scan and cleanup run as 01.04 jobs; five events through the outbox; numbering is not needed by files themselves (the sample document that carries them uses it) |

Departures from the pack: `core_files` carries the pack's fields plus category, extension, version chain, retention class and scan detail; two more tables (`core_file_uploads`, `core_file_settings`) are needed for resumable uploads and per-company settings. Permissions: `core.files.admin` (SYSADM, ITADM), `core.files.configure` (SYSADM); attaching and opening follow the permission the owning module gives on the record. Pages: File Storage Settings and the Sample Documents reference page that hosts the upload component.
