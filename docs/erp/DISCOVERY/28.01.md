## Decisions

| Requirement | Existing | Decision |
|---|---|---|
| FR-01 Providers and routing per feature | Integration hub | **Extend** the hub with three `ai` providers: `anthropic` (Messages API), `openai_compatible` (Azure OpenAI / self-hosted) and `sandbox` (no network). **New** `ai_providers` names the connector, model and prices; each feature version names its provider (routing). |
| FR-02 Context as the requesting person | Module services | **Reuse**: a feature builds its context by calling permission-checked services as the person (the variance narrative calls the 27.08 explainer). A refusal blocks the call and is logged; masked values and sensitive keys are dropped. |
| FR-03 Prompt and tool registry, versions | — | **New** `aiFeatures.register` in code: versioned prompt, tools READ or DRAFT only. A tool named for approve, post, pay, delete, cancel, reverse or release is refused at start-up. |
| FR-04 Logging, retention, redaction | Hub log | **New** `ai_logs`: references, redacted prompt (with a hash) and answer, tokens, cost, user, feature and outcome. PAN, Aadhaar, phone, e-mail, IFSC and account numbers are redacted. A daily purge applies the company's retention. |
| FR-05 Enablement, quotas, budgets, alerts, kill switch | — | **New** `ai_features` versions (roles, projects, quotas) and `ai_controls` (kill switch, retention). Per-person daily calls and a monthly budget, alert at a threshold, kill switch with event and notification. |
| FR-06 Evaluation harness | — | **New**: the cases of each feature run through the gateway with the rights of its enabled role; a version is sent for approval only when every case passes. |
| BR-01 Never approves, posts, pays or deletes; labelled | — | Enforced at registration (tools) and in the system prompt; every answer carries "AI-generated — verify". |
| §9 Enabling for production: SYSADM → DIR | Workflow | **Reuse** `createFlow` with document type `AI_FEATURE`, approver DIR. Switching off needs no approval; switching on again is a new version. |
| Roles | Role templates | SYSADM/ITADM configure, DIR approves and may pull the kill switch, AUD reads and exports the log; `ai.provider.manage` and `ai.kill_switch.manage` are added to the permission baseline. |
| Module | — | **New** server module `ai` (registry, ARCHITECTURE.md) and client module `ai`. |
