## Decisions

| Requirement | Existing | Decision |
|---|---|---|
| FR-01 Public catalogue with stable versions; deprecation | Internal routes and their policy | **New** gateway at `/api/public/{version}`: a catalogue of internal routes (v1), unknown versions refused, deprecated routes answer with Deprecation, Sunset and Link headers, then 410 after their sunset. Each call is handed to the internal API as the service account, so its permission, validation, idempotency, read-only and audit stages run unchanged (BR-01). **New** bulk endpoint re-enters the gateway per call. |
| FR-02 Service accounts with scopes mapped to permissions and data scope; key rotation | User type, role engine | **New** `api_clients` with a service user and role, scopes (each a set of permission keys and event prefixes), optional projects; the token's actor holds only the scopes' permissions, for those projects only. **New** `api_tokens` (hashed, one hour). Rotation keeps the old secret 24 hours; revocation ends tokens and webhooks. |
| FR-03 Webhooks with HMAC signatures, retries, delivery logs, replay | Event bus, signature helpers, vault | **New** `api_webhooks` (events within the client's scopes, encrypted secret) and `api_webhook_deliveries`: a bus consumer queues one delivery per event and webhook (masked payload); a job posts it signed, retries six times with back-off (1, 5, 30, 120, 360 minutes), keeps each outcome; test and replay. |
| FR-04 Developer portal: docs, try-it in sandbox, snippets, changelog | — | **New** portal tab: getting started, endpoints with curl/JavaScript/Python snippets, try-it from the browser with a sandbox client, signature guide, events by scope, changelog and deprecation policy. |
| FR-05 Usage analytics and rate-limit tiers | Per-person limiter | **New** tiers (BASIC 60, STANDARD 300, PREMIUM 1200 calls a minute) with RateLimit headers and 429; **new** `api_usage` per client, day and endpoint. |
| Section 9 New client with write scopes: ITADM → DIR | Approval engine | **Reuse**: type `api_client_activation`, chain DIR; the client gets no token until approved. |
| Roles | Templates | ITADM manages; DIR approves (view, portal); AUD and SYSADM read and use the portal. |
